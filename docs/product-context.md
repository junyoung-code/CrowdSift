# CrowdSift Product Context

## 제품 한 줄 설명

CrowdSift는 한국의 YouTube 크리에이터가 댓글 속 유용한 신호를 발견하고 유해한 반응을 안전하게 관리하도록 돕는 AI 기반 댓글 운영 도구다.

## 해결하려는 문제

댓글이 많아질수록 크리에이터는 반복 질문과 건설적인 피드백을 놓치고, 악성 댓글을 직접 읽으며 소진된다. 기존 댓글 관리 방식은 삭제와 차단에는 초점을 두지만, 댓글에서 다음 콘텐츠 아이디어와 시청자 요구를 발견하는 일까지 충분히 돕지 못한다.

## 첫 번째 실제 흐름

현재 가장 중요한 범위는 다음 하나다.

선택한 시작 날짜 `YYYY-MM-DD`는 Asia/Seoul 기준 `00:00:00`부터 포함한다.

```text
YouTube 연결
→ 시작 날짜 선택
→ 연결 채널의 최신 댓글부터 날짜까지 페이지 수집
→ 신규 댓글 AI 분류
→ 원문과 분석 결과를 DB에 분리 저장
→ Comment Inbox에서 확인
→ 이후 새 댓글을 60분마다 동기화
```

이 흐름이 실제 YouTube 데이터로 동작하기 전에는 랜딩 페이지 확장, 전체 대시보드, 결제, 다중 플랫폼 지원을 우선하지 않는다.

- 한 번의 worker 실행은 작은 batch만 처리한다. production의 Supabase Cron은 5분마다 Vercel worker를 깨워 중단된 backfill과 분류를 이어가지만, 정상 상태에서 YouTube 새 댓글을 가져오는 DB 일정은 60분 간격이다. 앱 URL과 worker secret은 Supabase Vault에 보관한다.
- 원문이 처음 저장된 신규 댓글만 의미 분석 → 계약 검증 → 명시적 정책 → CAUTION 재작성·독립 검증 경로로 보낸다. 중복 댓글은 모델 비용을 다시 발생시키지 않으며, 수정된 수치와 payload 관찰은 원문과 별도로 남긴다.
- 시작 날짜가 오래될수록 YouTube page·quota와 신규 댓글의 OpenAI 분석 비용이 증가한다.
- 자동 수집은 게시된 댓글 읽기와 분석까지만 수행한다. 실제 숨김·삭제·신고 같은 moderation action은 사용자의 명시적 확인 없이는 실행하지 않는다.

### 분류 품질 수동 검증

`/app/videos`의 영상 하나·20 / 30 / 50개 가져오기 흐름은 기본 onboarding 경로가 아니라 분류 품질을 수동으로 검증하는 보조 경로다.

```text
영상 하나 선택
→ 댓글 20 / 30 / 50개 가져오기
→ AI 분류
→ 원문과 분석 결과를 DB에 분리 저장
→ Comment Inbox에서 확인
```

### 로컬 공개 URL 검증 경로

본인 채널 OAuth 연결 전에도 분류 품질과 저장 흐름을 시험할 수 있도록 로컬 개발 환경에 한해 공개 영상 URL 읽기 전용 경로를 제공한다.

```text
CrowdSift 로그인
→ 공개 YouTube 영상 URL 확인
→ 댓글 총 20 / 50 / 100 / 1,000개 또는 전체 댓글 선택
→ 최상위 댓글과 답글을 함께 수집
→ 동일한 규칙·1차 AI·필요 시 2차 AI 분석
→ 공개 URL · 읽기 전용 출처로 DB 저장
→ Comment Inbox에서 확인
```

- 영상 소유자의 OAuth 인증 없이 공개·댓글 활성화 영상만 읽는다.
- 기본값은 20개이며 선택 수는 최상위 댓글과 답글을 합친 총 수다.
- 수집은 페이지별 원문·커서를 함께 저장하고, 다시 열린 개발자 도구는 최근 작업을 복원한다. 분석은 완료된 단계부터 재개하며 실패한 항목만 재시도할 수 있다. [복구·로그 동작](comment-job-recovery.md)을 따른다.
- 전체 댓글은 공개 API의 마지막 페이지까지 댓글과 답글을 수집한다. 영상의 표시 댓글 수는 비용 추정에만 사용하며 수집 제한으로 사용하지 않는다.
- 답글 없는 최상위 댓글도 가져오고, 답글은 부모 댓글이 있을 때만 저장한다.
- 공개 URL 결과에는 숨김·삭제 권한이 없고 개인화 RAG나 학습 opt-in을 허용하지 않는다.
- 로컬 fixture는 외부 API를 호출하지 않으며 화면에 항상 `TEST FIXTURE`로 표시한다.
- fixture는 실제 서비스와 동일한 의미 분석 계약·정책·저장·재작성 흐름을 사용한다. 모델 역할만 deterministic TEST FIXTURE로 바꾸며 실제 모델 정확도의 근거로 사용하지 않는다.
- 실제 API Key를 사용하는 live 검증은 개발 환경에서만 명시적으로 활성화한다.

세부 설계와 검증 순서는 다음 문서를 따른다.

- `docs/superpowers/specs/2026-07-24-public-youtube-read-only-dev-mode-design.md`
- `docs/manual-public-youtube-verification.md`

## 핵심 사용자 경험

- 댓글을 질문, 건설적 피드백, 유해하지만 참고할 신호가 있는 댓글, 순수 악성 댓글, 스팸, 판단 어려움 등으로 분류한다.
- 공격이 없는 안전 댓글은 Inbox에서 작성자 정보와 원문을 바로 보여준다. 타인 대상 공격으로 등급은 안전이어도 원문은 기본적으로 가린다. 주의 댓글은 작성자 정보와 정리된 의견을 보여주고, 원문은 경고 확인 후 펼친다.
- 위험 댓글은 보호 안내를 보여주며 순화문을 생성하지 않는다. 작성자 정보는 항상 표시하고 원문은 사용자가 경고를 확인한 뒤 펼쳐 볼 수 있다.
- 펼친 위험 원문은 접을 수 있고 새로고침하면 다시 가려진 상태로 시작한다.
- AI는 조치를 추천할 수 있지만 실제 숨김·거절·삭제는 사용자가 확인한 뒤 수행한다.
- 조치 전에 원문과 출처 메타데이터를 보존하고, 조치 결과와 시간을 기록한다.

## 인증과 세션

- CrowdSift 로그인은 Google을 기본 방식으로 사용한다.
- 현재 로그인 화면에는 Google 로그인만 노출한다. 이메일 Magic Link 구현은 향후 확장을 위해 유지하되 화면에서는 숨긴다.
- 로그인용 Google OAuth는 CrowdSift 사용자 인증만 담당한다. YouTube 채널 조회와 댓글 조치 권한을 위한 OAuth는 로그인 흐름과 별도로 연결한다.
- 같은 브라우저의 Supabase 세션은 사용자가 명시적으로 로그아웃하거나 보안상 폐기될 때까지 refresh token으로 갱신한다.
- 로컬 Magic Link 메일은 Gmail로 발송하지 않고 Mailpit에서만 확인한다. 프로덕션에서는 별도 SMTP를 설정한다.

## 이후 기능 순서

1. Comment Inbox
2. 반복 질문을 묶는 Q&A Radar
3. 유용한 피드백과 추세를 요약하는 Signal Digest
4. 조치 전 원문과 메타데이터를 보존하는 Evidence Vault
5. 사용자가 직접 조정하는 Moderation Rules

## 데이터 원칙

- 원본 댓글은 수정하거나 정제된 문장으로 덮어쓰지 않는다.
- AI 결과, 정제된 피드백, 사용자 조치, 증거, 감사 로그를 분리한다.
- 모델명, 프롬프트 버전, 처리 시각, 신뢰도, 사용자 수정 이력을 남길 수 있어야 한다.
- 불확실하거나 위험도가 높은 판단은 자동 조치하지 않고 사용자 검토로 보낸다.

## 크리에이터별 AI 개인화

CrowdSift는 크리에이터마다 별도 대형 모델을 만들지 않는다. 하나의 공통 분석 모델에 크리에이터별 정책과 과거 피드백을 결합한다.

1. **공통 OpenAI 모델**: 한국어 댓글의 의미, 욕설, 비꼼, 질문과 건설적 피드백을 구조화해 분석한다.
2. **크리에이터별 정책**: 금지어, 허용어, 카테고리별 민감도와 선호 조치를 별도 저장한다.
3. **크리에이터별 피드백 RAG**: 새 댓글과 비슷한 과거 승인·거절·수정 사례를 같은 크리에이터의 데이터에서만 찾아 분석에 제공한다.
4. **규칙 엔진**: 정확한 금지어, 반복 광고, 의심스러운 URL처럼 결정적으로 검사할 수 있는 신호를 코드로 처리한다.
5. **사용자 확인**: AI와 규칙 엔진은 조치를 추천하지만 실제 숨김·거절·삭제는 사용자가 확인한 뒤 수행한다.
6. **선택적 공통 Fine-tuning**: 충분한 한국어 평가 데이터가 쌓이고 기본 모델보다 개선됐음이 입증된 경우에만 후속 단계로 검토한다.

금지어 하나만으로 댓글을 확정 분류하지 않는다. 같은 표현도 문맥과 채널 성격에 따라 칭찬 또는 공격이 될 수 있으므로 규칙 결과, 댓글 문맥, 크리에이터 정책과 과거 판단을 함께 사용한다.

사용자 정책, 사용자 수정 이력, 평가 세트, 학습 세트와 모델 버전은 서로 분리한다. 사용자 피드백을 학습 데이터로 사용하려면 명시적인 동의, 테넌트 분리, 삭제 가능성, 보존 기간과 품질 검토가 필요하다.

## 기술 방향

- Next.js App Router, TypeScript, Tailwind CSS
- Supabase 데이터베이스와 인증·접근 제어
- Google OAuth와 YouTube Data API
- 구조화된 JSON을 반환하는 OpenAI API와 런타임 검증
- Vercel 배포와 Supabase Cron이 호출하는 인증된 bounded worker로 채널 backfill·incremental 수집과 분류를 재개

## Comment Inbox UI (2026-09-12)

- 랜딩의 아이보리·파란색 디자인을 이어가는 단일 댓글 목록을 사용한다. 영상 썸네일과 제목은 댓글 오른쪽에 표시하고 모바일에서는 아래에 배치한다.
- 첫 진입은 전체 댓글이다. 빠른 필터는 전체·안전·주의·위험·판단 보류이며, 상세 필터는 유형·분석 상태·조치 상태·기간이다.
- 기간은 서울 날짜 기준 오늘을 포함한 최근 7/30/90일이다. 기간과 상태 필터, 최신순·좋아요순 정렬은 DB에서 페이지를 나누기 전에 적용한다.
- 주의 댓글은 정제된 피드백과 ‘거친 표현 포함’을 보여 주고, 위험 댓글은 ‘위험 댓글 · 내용 보호됨’을 표시한다. 모든 등급의 댓글과 답글에서 저장된 작성자 이름과 프로필 사진을 표시한다. 원문은 경고 확인 후 불러온다.
- 답글은 목록 안에서 펼친다. AI 판단 수정과 기존 YouTube 조치는 댓글의 더보기 메뉴에 유지하며 실제 조치는 기존 확인 절차를 따른다. 좋아요는 수치만 표시하고 아직 지원하지 않는 싫어요·답글 작성 버튼은 노출하지 않는다.

## 화면 테마 기본값

- 첫 방문과 저장된 테마가 없거나 유효하지 않을 때는 다크 모드(검은 배경·흰 글씨)로 시작한다. 사용자가 선택한 라이트/다크 모드는 저장하여 다음 방문에도 유지한다.

## 댓글 관리 기준 UI (2026-09-13)

- 기존 `/app/settings/moderation`에서 작은 글씨의 2열 설정·미리보기를 사용한다. 모바일에서는 세로로 배치한다.
- 처음 저장하는 기준에는 외모 비하·가족 언급·반복 홍보를 선택해 둔다. 저장된 빈 선택은 그대로 유지한다. 추가 선택지는 사생활 추측·타인과 비교·스포일러이며 직접 내용을 추가할 수 있다.
- 선택된 칩은 둥근 남색 배경과 파란 ×, 미선택 칩은 +로 표시한다. 주의할 내용은 추가 검토 신호이며 단독으로 위험 등급을 확정하지 않는다.
- 일반적인 칭찬·관용 표현은 공통 모델이 문맥으로 이해한다. 채널 고유 표현은 허용하는 상황과 함께 저장한다. 기존 맥락 없는 허용어도 보존한다.
- 맥락 규칙은 기존 버전별 `phrase_rules`의 `context_exception`으로 보존하고, 소유 채널의 새 분석에 `allowedContexts`로 전달한다. 무조건 허용어로 평탄화하지 않는다. 공개 URL 및 소유권 불명 댓글에는 개인 프로필을 적용하지 않는다.
- 기본 미리보기는 `예시 댓글 · 예상 결과`라고 명시한다. 직접 입력 미리보기는 인증된 서버에서 현재 입력 맥락 규칙으로 의미 분석·정책·재작성·독립 검증을 실행한다. 입력 댓글과 결과를 DB에 저장하지 않으며, fixture 결과는 별도 표시한다. 영상·답글 문맥이 없는 미리보기는 실제 Inbox 판정과 다를 수 있다.
- 실제 숨김·삭제 확인 및 원문 보존은 기존 흐름을 유지한다. 저장한 기준은 이후 분석부터 적용한다.

### 과거 댓글 분류 기준 (2026-09-13, 과거 결과 조회 전용)

- 1·2차는 공통 기준을 쓴다. 단순 체중·결혼·가족 언급, 질문·축하·관찰은 공격 근거 없이 올리지 않는다.
- 안전: 온건한 의견·질문·칭찬. 주의: 무례한 참견·질책·거친 농담. 위험: 명확한 비하·협박·성희롱 등 실제 공격.
- API 출력에 원문 근거 구절, 짧은 설명, 중요한 미해결 문맥을 기록한다. 근거는 AI 기록으로 보존하며 순화문과 분리한다.
- 2차가 근거와 함께 문맥을 해소하면 1차의 모호함·개인 공격 오탐을 해소할 수 있다. 미해결 중요 문맥, 명시적 강한 위험의 불일치는 검토 대상으로 남긴다.
- 근거 필드가 없는 과거 기록은 이전 확정 규칙으로 재현한다. 기존 결과를 새 모델 결과처럼 바꾸지 않는다.
- 기본 모델은 검증 전 교체하지 않는다. 2차 모델에 gpt-5.6-luna를 선택하면 xhigh로 비교하며 1차는 none을 유지한다. Astra는 사용하지 않는다.


### 의미 분석 기반 분류 (2026-09-17, 현재 승인 정책)

- 부정적 평가·불만·직설적 취향은 harm이 아니다. 불필요한 인격 공격·조롱·성적/외모 비하·위협·비인간화·근거 없는 동기 추측만 분리한다.
- 의미 자체를 복원할 수 없을 때 HOLD. API 오류·낮은 confidence는 HOLD로 성공 처리하지 않는다.
- 크리에이터/콘텐츠 관련 공격 없음 SAFE. 공격을 제거해도 검증된 feedback claim이 남으면 CAUTION, 남지 않으면 RISK.
- 위협이 섞여도 피드백과 분리 가능하면 CAUTION. 등급은 심각도 순서가 아니며 severity/criticalHarm은 독립 신호다.
- 확인된 타인 대상 공격과 스팸은 별도 표시하며 등급을 덮어쓰지 않는다. unknown/general 대상은 확인된 타인으로 간주하지 않는다.
- 잔존 가치는 존재하는 claim ID 목록에서 코드로 계산한다. 원문 근거를 검사하고, 중립 재작성은 별도 의미 검증 호출로 확인한다.
- 재작성은 CAUTION만 수행한다. 실패하면 한 번 수정하고 다시 실패하면 피드백 정리 실패 상태를 보여준다. 미검증 feedbackCore를 노출하지 않는다.
- 원문·analysis·verdict·rewrite·사용자 수정·audit을 분리한다. 단계 성공 결과와 입력/모델 설정 snapshot은 재시도에서 재사용한다.
- 공개 URL에는 개인화를 적용하지 않는다. 이전 등급만 있는 교정은 새 정답으로 취급하지 않으며 이유·맥락이 있는 교정만 참고한다.
- 보호 강도·민감 주제·말투·이모티콘은 새 등급 정책에 적용하지 않는다. 채널 맥락 규칙만 분석에 반영한다.
- 모델 기본값은 없다. 모델/추론 A/B와 사람 검수 holdout(100/100/100 + HOLD 30건), 3회 평가를 거쳐 선택한다. 운영 활성화는 검증된 설정 식별자의 명시적 승인 후 수행한다.
- 2026-09-20 사용자 승인으로 운영 의미 분석 설정은 `gpt-5.6-luna` 분석 medium / 재작성 low / 검증 medium과 `context-v3`를 사용한다. 정확한 설정 식별자가 일치할 때만 실행한다.
- 구 기록은 보존하며 미완료 구 작업은 새 ID로 이관한다. 구·신 단계를 혼합하지 않는다.
- 실행 방법과 품질 지표는 `docs/semantic-classification.md`를 참고한다. 구조 검증과 실제 모델 정확도 95% 초과 달성은 별개다.
