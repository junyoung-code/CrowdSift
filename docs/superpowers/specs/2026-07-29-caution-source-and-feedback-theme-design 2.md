# Comment Inbox 주의 원문 공개와 AI 판단 수정 테마 보정 설계

**작성일:** 2026-07-29  
**상태:** 구현 전 승인 설계

## 목적

Comment Inbox의 원문 공개 기준을 사용자가 확정한 운영 방식에 맞추고, `AI 판단 수정` 폼이 라이트·다크 모드에서 일관된 대비를 갖도록 보정한다.

## 확정된 제품 결정

- `안전`과 `주의` 댓글은 Inbox 목록과 선택한 대화에서 작성자 정보와 원문을 즉시 표시한다.
- `위험` 댓글만 순화된 요약을 먼저 표시하고, 사용자가 경고를 확인한 뒤 작성자 정보와 원문을 펼쳐 본다.
- 이 기준은 최상위 댓글과 모든 대댓글에 동일하게 적용한다.
- 테마를 전환해도 원문 공개 여부, 선택한 대화, 필터와 수정 중인 값은 바뀌지 않는다.
- 원문과 AI 분석·순화 피드백은 계속 별도 데이터로 보존한다.
- AI 판단 수정은 감사 기록으로 저장하며 원본 댓글을 덮어쓰지 않는다.

## 검토한 접근 방식

### A. Inbox 조회 정책에서 안전·주의 원문을 함께 반환

읽기 전용 Inbox 조회 함수가 `안전` 또는 `주의`이고 삭제되지 않은 원문을 반환한다. 클라이언트는 반환된 원문을 즉시 표시하고 `위험`에만 기존 경고 공개 흐름을 사용한다.

장점:

- 최초 화면에서 원문이 바로 보여 깜빡임이나 추가 요청이 없다.
- 최상위 댓글과 대댓글에 같은 규칙을 적용하기 쉽다.
- `위험` 원문이 초기 응답에 포함되지 않는 기존 보호 경계를 유지한다.

단점:

- 데이터베이스 조회 함수와 pgTAP 검증을 함께 갱신해야 한다.

**결정:** 채택한다.

### B. 화면이 열린 뒤 주의 원문을 별도 API로 자동 요청

기존 조회 정책을 유지하고 클라이언트가 `주의`마다 원문 공개 API를 자동 호출한다.

장점:

- 기존 Inbox 조회 함수의 변경이 적다.

단점:

- 댓글과 대댓글 수만큼 추가 요청이 발생할 수 있다.
- 원문이 늦게 나타나며 로딩 상태와 실패 처리가 추가된다.
- 사용자 확인이 필요 없는 `주의`에도 경고 공개 API를 우회적으로 재사용하게 된다.

**결정:** 채택하지 않는다.

## 데이터 흐름

1. 서버가 현재 워크스페이스의 Inbox 대화 조회 함수를 호출한다.
2. 조회 함수는 분석 등급이 `safe` 또는 `caution`이고 출처가 삭제되지 않은 경우 표시 원문을 반환한다.
3. 저장소 계층은 원문 필드를 최상위 댓글과 대댓글 도메인 객체에 그대로 매핑한다.
4. Comment Inbox는 다음 기준으로 렌더링한다.
   - 목록의 `safe`, `caution`: `safeSourceText` 원문을 미리보기로 렌더링
   - 선택한 대화의 `safe`, `caution`: 작성자와 원문을 즉시 렌더링
   - `risk`: 목록에는 순화 요약을 유지하고 선택한 대화에는 `원문 확인` 경고 흐름 렌더링
   - 원문이 삭제됐거나 사용할 수 없는 `safe`, `caution`: 목록에서 기존 AI 요약으로 대체
5. AI 판단 수정은 기존 저장 경로와 감사 로그를 유지한다.

기존 `safeSourceText` 필드 이름은 변경 범위를 줄이기 위해 이번 수정에서 유지하되, 의미는 “초기 화면에 표시 가능한 출처 원문”으로 확장한다. 새로운 기능에서는 이 의미를 문서와 테스트에 명시한다.

## 화면과 테마

`AI 판단 수정` 영역의 다음 요소에서 직접 지정된 다크 배경색을 제거한다.

- 댓글 유형 셀렉트
- 검토 등급 셀렉트
- 추천 조치 셀렉트
- 순화된 피드백 텍스트 영역
- 저장 버튼과 폼 경계

모든 중립색은 기존 제품·Inbox 테마 토큰에서 가져온다.

- 라이트 모드: 밝은 표면, 짙은 본문, 분명한 테두리와 포커스 링
- 다크 모드: 어두운 표면, 밝은 본문, 동일한 의미색과 포커스 링
- `안전·주의·위험` 상태색은 테마와 무관하게 의미를 유지한다.

레이아웃, 입력 크기, 폼 순서와 저장 동작은 변경하지 않는다.

## 오류와 보호 동작

- 표시 가능한 원문이 없거나 삭제된 경우에는 기존 “원문을 불러올 수 없음” 상태를 표시한다.
- `위험` 원문은 초기 Inbox 대화 응답에 포함하지 않는다.
- 위험 원문 공개 API의 경고 확인, 펼치기, 접기와 새로고침 시 재보호 동작을 유지한다.
- AI 판단 수정 실패 시 현재 오류 메시지와 입력값을 유지한다.

## 테스트 기준

- `안전` 최상위 댓글과 대댓글의 원문이 처음부터 보인다.
- `주의` 최상위 댓글과 대댓글의 원문이 처음부터 보이고 `원문 확인` 버튼이 없다.
- Inbox 목록에서 `안전·주의`는 원문을 표시하고 `위험`은 순화 요약을 표시한다.
- 원문을 사용할 수 없는 `안전·주의` 목록 항목은 기존 AI 요약으로 대체한다.
- `위험` 최상위 댓글과 대댓글의 원문은 초기 DOM과 조회 응답에 없고 경고 공개 흐름만 보인다.
- 삭제된 출처 원문은 등급과 관계없이 표시하지 않는다.
- 라이트 모드에서 AI 판단 수정 컨트롤이 밝은 테마 토큰을 사용한다.
- 다크 모드에서 같은 컨트롤이 어두운 테마 토큰을 사용한다.
- 수정 저장, 대화 선택, 답글 수 표시와 기존 위험 원문 공개 테스트가 회귀하지 않는다.
- 전체 단위 테스트, 데이터베이스 테스트, lint와 production build가 통과한다.

## 문서 정합성

이 결정은 기존 `docs/product-context.md`의 “주의·위험을 모두 기본 숨김” 기준을 대체한다. 구현과 함께 해당 문서를 다음 기준으로 갱신한다.

- 안전·주의: 작성자와 원문 즉시 표시
- 위험: 경고 확인 후 원문 표시
