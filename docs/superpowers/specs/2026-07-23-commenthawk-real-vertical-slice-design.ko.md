# CommentHawk 첫 실제 수직 슬라이스 설계

- **상태:** 승인된 설계
- **작성일:** 2026-07-23
- **우선 대상:** 데스크톱 웹
- **영문 원본:** [2026-07-23-commenthawk-real-vertical-slice-design.md](./2026-07-23-commenthawk-real-vertical-slice-design.md)

## 1. 목표

CommentHawk의 첫 실제 제품 흐름을 구현한다.

```text
BrandBastion을 참고한 랜딩 페이지
→ CommentHawk 로그인
→ 크리에이터가 소유한 YouTube 채널 하나 연결
→ 영상 하나 선택
→ 실제 댓글 20~50개를 초기 검증용으로 가져오기
→ 2단계 AI 분류와 크리에이터별 개인화 실행
→ 원본 데이터와 파생 데이터를 분리 저장
→ 실제 결과를 크리에이터 대시보드와 Comment Inbox에 표시
→ 크리에이터가 결과를 검토·수정하고 댓글 관리 조치를 명시적으로 승인
```

초기 댓글 20~50개는 제품의 최대 한도가 아니라 실제 연동을 검증하기 위한 첫 배치다. 이후 핵심 도메인 인터페이스를 교체하지 않고도 페이지네이션, 더 큰 동기화 작업과 백그라운드 처리를 추가할 수 있어야 한다.

## 3. 범위

### 포함

- CommentHawk 고유 브랜딩과 BrandBastion을 참고한 시각 완성도를 갖춘 데스크톱 랜딩 페이지
- CommentHawk 앱 세션을 위한 Supabase 이메일 매직 링크 인증
- 앱 로그인과 분리된 YouTube 접근용 Google OAuth
- 연결할 수 있는 채널이 여러 개일 때 크리에이터가 소유한 YouTube 채널 하나 선택
- 연결된 채널에서 영상 하나 선택
- 최상위 댓글과 가져올 수 있는 답글 20~50개를 초기 배치로 수집
- 수정 불가능한 원본 댓글과 출처 메타데이터의 중복 없는 저장
- 크리에이터 정책, 문구 규칙, 문맥 예외와 선호 조치
- 1차 분류를 위한 결정적 규칙과 공통 OpenAI 모델
- 같은 크리에이터의 과거 피드백 검색과 2차 문맥 분석
- 사용자에게 표시하는 검토 등급 `안전`, `주의`, `위험`
- 실제 크리에이터 대시보드와 Comment Inbox
- AI 결과와 분리된 크리에이터 수정 기록
- YouTube 댓글 조치 전 증거 보존과 명시적 사용자 확인
- 로딩, 빈 상태, 연결 해제, 일부 실패, 권한, 할당량, 재시도와 성공 상태
- 단위, 통합, 브라우저, 접근성과 한국어 평가 테스트

### 제외

- 모바일 전용 레이아웃과 모바일 앱
- Instagram, TikTok과 다른 플랫폼의 실제 연동
- 결제와 가격 정책
- 여러 채널의 동시 운영
- 복잡한 팀 권한
- Q&A Radar
- Signal Digest
- 완성형 Evidence Vault 화면과 증거 내보내기
- 완성형 분석 대시보드
- 자동 답글
- 사용자의 승인 없는 자동 댓글 조치
- 법률적 결론이나 법적 성공 가능성 판단
- 실제 Fine-tuning 또는 크리에이터마다 별도 Fine-tuned 모델 운영

## 4. 제품 용어

화면에서는 다음 검토 등급을 사용한다.

| 저장값 | 한국어 표시 | 의미 |
|---|---|---|
| `safe` | 안전 | 충분한 신뢰도에서 중요한 문제나 정책 충돌이 발견되지 않아 검토 우선순위가 낮다. 법적·절대적 안전을 보장한다는 뜻은 아니다. |
| `caution` | 주의 | 문맥, 비꼼, 크리에이터별 표현, 유용한 내용과 공격적 표현의 혼합 또는 낮은 신뢰도 때문에 사람의 확인이 필요하다. |
| `risk` | 위험 | 피싱, 심각한 괴롭힘, 신빙성 있는 협박, 강한 공격이나 다른 우선 검토 신호 때문에 빠른 사람의 확인이 필요하다. |

모든 댓글은 저장되고 검색할 수 있어야 한다. 기본 검토함에는 `주의`와 `위험`을 먼저 보여준다. 색상만으로 등급을 구분하지 않고 텍스트와 아이콘을 함께 사용한다.

## 5. 사용자 경험

### 5.1 공개 랜딩 페이지

경로: `/`

저장된 BrandBastion 레퍼런스의 정보 흐름과 시각 품질을 참고하되, BrandBastion의 자산, 소스 코드, 문구, 로고, 고객 주장, 고객사 로고, 일러스트, 통계 수치와 정확한 화면 구조는 복제하지 않는다.

섹션 구성:

1. CommentHawk 아이덴티티, 제품 내비게이션, 로그인과 주요 CTA가 있는 헤더
2. `references/brandbastion/09-dashboard-hero-detail.png`를 참고한 브라우저형 CommentHawk 제품 미리보기와 큰 한국어 Hero 문구
3. 가져온 댓글, 분석 완료, `주의`, `위험`과 AI 요약을 보여주는 플로팅 미리보기 카드
4. 악성 원문 노출, 유용한 피드백 유실과 일관성 없는 수동 판단을 설명하는 문제 카드 3개
5. 안전한 1차 분류, 크리에이터별 관리와 유용한 피드백 보존을 설명하는 솔루션 3개
6. 2단계 AI 분석 과정 설명
7. `references/brandbastion/06-ai-processing.png`를 참고한 어두운 AI 처리 섹션
8. YouTube만 실제 지원한다고 명확히 보여주고 다른 플랫폼이 연결된 것처럼 표현하지 않는 YouTube-first 연동 섹션
9. 최종 연결 CTA

Hero 안의 대시보드는 `제품 예시 화면`이라고 명확히 표시한다. 예시 값은 인증된 실제 대시보드 데이터 경로와 완전히 분리한다.

### 5.2 CommentHawk 로그인

경로: `/auth/sign-in`

앱 세션은 Supabase 이메일 매직 링크 인증을 사용한다. YouTube 권한 부여는 별도 단계로 유지한다. 사용자는 YouTube 권한을 제공하지 않아도 CommentHawk에 로그인할 수 있고, CommentHawk 계정을 잃지 않고도 YouTube 연결을 해제할 수 있어야 한다.

### 5.3 YouTube 연결

경로: `/app/connect/youtube`

흐름:

1. 로그인한 사용자가 Google OAuth를 시작한다.
2. 서버가 OAuth `state`를 검증하고 인증 코드를 토큰으로 교환한다.
3. CommentHawk가 인증된 Google 사용자에게 연결 가능한 크리에이터 소유 채널을 불러온다.
4. 채널이 하나면 미리 선택한 후 사용자에게 확인받는다.
5. 채널이 여러 개면 사용자가 정확히 하나를 선택한다.
6. CommentHawk가 채널 메타데이터와 암호화된 토큰을 저장한다.
7. 사용자는 연결 해제, 재연결과 만료·철회된 권한 복구를 할 수 있다.

초기 댓글 가져오기는 최소 읽기 권한만 요청한다. 사용자가 실제 숨김·거절·삭제 조치를 처음 선택할 때 점진적 권한 부여를 통해 필요한 댓글 관리 권한을 추가로 요청한다.

저장하는 채널 정보는 제품에 필요한 범위로 제한한다. 채널 ID, 제목, 사용할 수 있는 경우 핸들 또는 URL, 썸네일, 소유·연결 상태, 승인된 권한과 동기화 시각만 저장한다.

### 5.4 영상 선택과 댓글 가져오기

경로: `/app/videos`

사용자는 선택한 채널의 최근 영상을 확인하고 영상 하나를 선택한 다음 초기 가져오기 수량을 20~50개 사이에서 선택한다. 진행 상태에는 요청 수, 가져온 수, 저장한 수, 중복으로 건너뛴 수와 실패 수를 표시한다.

첫 수직 슬라이스는 검증용 배치를 지원한다. 서비스 경계는 페이지 토큰과 제한 수를 입력받도록 만들어 후속 작업에서 UI 소비 코드를 바꾸지 않고 `더 가져오기`, 정기 동기화와 백그라운드 처리를 추가할 수 있어야 한다.

### 5.5 크리에이터 대시보드

경로: `/app`

로그인 후에는 실제로 저장된 데이터만 표시한다.

상단 카드:

- 가져온 댓글
- 분석 완료
- `주의`
- `위험`

주요 내용:

- 연결된 채널과 연결 상태
- 선택된 영상과 마지막 성공 가져오기 시각
- 댓글 가져오기와 분석 진행 상태
- 실제 `안전 / 주의 / 위험` 분포
- 우선순위가 높은 `주의`와 `위험` 댓글
- 최근 크리에이터 수정 및 댓글 조치 기록
- Comment Inbox 이동 CTA
- 실제 분석 데이터가 충분할 때만 표시하는 AI 요약

연결되지 않은 대시보드에는 통계 수치 대신 YouTube 채널 연결 안내를 표시한다. 예시 값을 실제 연결 결과처럼 보여주지 않는다.

### 5.6 Comment Inbox

경로: `/app/inbox`

Inbox는 마케팅 페이지보다 정보 밀도가 높고 차분한 작업 화면으로 만든다.

기능:

- `주의`와 `위험`을 포함하는 기본 `검토 필요` 목록
- `안전 / 주의 / 위험` 필터
- 댓글 유형, 영상, 분석 상태, 조치 상태와 신뢰도 필터
- 허용된 원본·파생 필드 검색
- 유해 원문보다 순화된 피드백을 먼저 표시
- 유해 원문을 보기 전 명시적인 경고 확인
- 출처, 규칙 신호, AI 분석, 크리에이터 정책 일치, 검색된 사례와 최종 크리에이터 결정을 구분하는 상세 패널
- 유형, 검토 등급, 추천 조치와 순화 피드백 수정
- 명시적인 댓글 조치 확인
- 증거와 감사 기록

## 6. 애플리케이션 아키텍처

하나의 Next.js 16 App Router 애플리케이션 안에 역할이 명확한 서버 전용 모듈을 둔다.

```text
React UI
→ Server Action 또는 Route Handler
→ 도메인 서비스
   ├── 애플리케이션 인증
   ├── YouTube 권한 부여와 댓글 수집
   ├── 결정적 규칙
   ├── AI 1차 분류
   ├── 크리에이터 피드백 검색
   ├── 2차 문맥 분석
   ├── 크리에이터 검토
   ├── 댓글 조치 실행
   └── 증거 및 감사 기록
→ Supabase Postgres
```

React 컴포넌트에서 외부 SDK를 직접 호출하지 않는다. 서비스는 애플리케이션이 소유한 타입을 노출해 Google, OpenAI 또는 저장소 구현을 바꾸더라도 UI 컴포넌트를 다시 작성하지 않도록 한다.

초기에는 댓글 가져오기와 분석을 웹 애플리케이션 프로세스에서 실행하더라도 작업 상태를 DB에 저장한다. 향후 백그라운드 워커도 같은 작업 레코드와 서비스 인터페이스를 사용한다.

## 7. 데이터 경계

크리에이터에게 속한 모든 행에는 `workspace_id`를 둔다. 첫 수직 슬라이스에서는 사용자 한 명당 소유자 워크스페이스 하나를 만들되, 이후 팀 기능을 위해 스키마에서 워크스페이스 소유 관계를 명확히 유지한다.

### 7.1 사용자와 연결

- `profiles`: Supabase Auth 사용자와 연결된 앱 사용자 프로필
- `workspaces`: 테넌트 경계와 크리에이터 설정
- `workspace_members`: 소유자 멤버십. 이번 범위에서는 추가 역할을 화면에 제공하지 않음
- `youtube_connections`: 암호화된 접근·갱신 토큰 정보, 권한, 상태와 만료 시각
- `youtube_channels`: 선택된 출처 채널 메타데이터
- `youtube_videos`: 가져온 출처 영상 메타데이터

### 7.2 원본 댓글 수집

- `comment_import_jobs`: 요청 제한, 페이지 커서, 상태, 처리 수, 재시도 정보와 시각
- `raw_comments`: 안정적인 YouTube 식별자, 부모 관계, 사용할 수 있는 작성자 메타데이터, 변경하지 않는 표시·원본 텍스트, 작성·수정 시각, 사용할 수 있는 경우 관리 상태, 수집 시각, 가져오기 작업과 출처 삭제 표시
- `raw_comment_payloads`: 변경 불가능한 원본 댓글과 연결된 보존용 API 응답

원본의 고유 키:

```text
workspace_id + youtube_comment_id
```

순화된 텍스트와 AI 결과는 `raw_comments`를 절대 수정하지 않는다.

### 7.3 크리에이터 정책

- `creator_policies`: 유형별 민감도, 기본 추천, 유해 원문 표시 선호, 버전과 수정 시각
- `phrase_rules`: 금지어, 허용어, 문맥 예외, 정규화된 일치 형태, 활성화 상태와 버전
- `rule_evaluations`: 댓글별 일치 규칙, 결정적 신호와 규칙 엔진 버전

금지어는 신호이며 자동 조치의 최종 판결이 아니다. 허용어와 문맥 예외는 검토 경로를 바꿀 수 있지만 댓글 관리 조치를 직접 실행할 수 없다.

### 7.4 AI와 개인화

- `analysis_jobs`: 여러 댓글 분석 작업의 생명주기와 처리 수
- `model_runs`: 제공자, 모델 식별자, 프롬프트 버전, 스키마 버전, 정책 버전, 지연 시간, 사용량, 상태와 오류 메타데이터
- `comment_analyses`: 유형, 신뢰도, 검토 등급, 유해성, 스팸·피싱 확률, 유용한 피드백 포함 여부, 추천 조치, 수동 검토 여부, 설명과 판단 근거 식별자
- `sanitized_feedback`: 분석과 연결된 중립적 파생 피드백 또는 유용한 신호가 없다는 명시적 결과
- `creator_feedback`: 크리에이터 승인, 거절, 수정 필드, 수정된 순화 피드백과 동의 값
- `feedback_embeddings`: 임베딩 벡터, 출처 피드백, 임베딩 모델과 삭제 상태
- `evaluation_cases`: 실제 사용자 데이터와 분리된 사람이 검토한 한국어 평가 사례와 기대 결과

개인화 동의와 향후 학습 동의는 분리한다.

- `use_for_personalization`: 같은 워크스페이스 안의 RAG 검색에 사용할 수 있음
- `use_for_training`: 향후 학습 후보임을 표시할 뿐 데이터를 업로드하거나 학습을 시작하지 않음

### 7.5 조치, 증거와 감사

- `moderation_action_requests`: 요청 조치, 대상, 실행자, 확인 시각, 멱등성 키, 실행 상태, 결과와 오류
- `evidence_records`: 댓글 조치 전에 확보한 변경 불가능한 원본 스냅샷과 사용할 수 있는 메타데이터
- `audit_logs`: 실행자, 이벤트 유형, 대상 참조, 시각과 민감하지 않은 이벤트 메타데이터

## 8. 2단계 분석

### 8.1 0단계: 원본 보존

분류 전에 원본 댓글과 사용할 수 있는 출처 메타데이터를 저장한다. 원본 대신 순화된 문장을 기록하거나 저장하지 않는다.

### 8.2 1단계: 모든 댓글의 빠른 분류

입력:

- 변경 불가능한 원본 댓글
- 영상 제목과 허용된 출처 문맥
- 결정적 규칙 결과
- 현재 크리에이터 정책 요약

출력:

- 명시적인 댓글 유형
- 신뢰도
- 초기 `안전 / 주의 / 위험`
- 유해성, 스팸과 피싱 신호
- 유용한 피드백 포함 여부
- 2차 분석 실행 여부와 이유

명시적인 댓글 유형:

```text
positive
neutral
question
constructive_feedback
toxic_but_actionable
abusive_no_signal
spam_advertisement
phishing
harassment
threat_or_serious_risk
uncertain
```

### 8.3 크리에이터 피드백 검색

검색용 임베딩을 만들고 현재 워크스페이스에서 활성화된 `use_for_personalization` 사례만 검색한다. 승인됐거나 수정된 사례를 최대 5개 반환하고 검색된 모든 식별자와 유사도 점수를 기록한다.

초기 유사도 기준은 `0.78`이다. 평가 결과에 따라 과거 분석 기록을 바꾸지 않고 조정할 수 있도록 버전이 있는 분석 설정에 저장한다.

### 8.4 2단계: 문맥 기반 정밀 분석

다음 중 하나라도 해당하면 2차 분석을 실행한다.

- 1차 결과가 `주의` 또는 `위험`
- 1차 신뢰도가 `0.85` 미만
- 금지어, 허용어 또는 문맥 예외 규칙이 일치
- 크리에이터 과거 피드백과의 유사도가 `0.78` 이상
- 공격적 표현과 유용할 수 있는 피드백이 함께 존재
- 비꼼, 인용, 은어, 띄어쓰기 변형 또는 다른 문맥 의존 표현이 존재

입력:

- 변경 불가능한 원본과 사용할 수 있는 댓글 스레드·영상 문맥
- 1차 결과와 결정적 신호
- 현재 크리에이터 정책과 문구 규칙 버전
- 같은 워크스페이스의 유사 피드백 최대 5개

출력:

- 최종 댓글 유형과 신뢰도
- 최종 `안전 / 주의 / 위험`
- 원문에 근거한 순화 피드백 또는 `null`
- 정규화된 질문 또는 `null`
- 추천 조치
- 수동 검토 및 증거 검토 여부
- 크리에이터에게 보여줄 설명
- 규칙, 피드백, 정책, 모델, 프롬프트와 스키마 판단 근거

2차 분석은 1차 결과를 변경할 수 있지만 두 분석 실행을 모두 보존한다.

### 8.5 크리에이터 검토

크리에이터가 결과를 수정하면 새로운 `creator_feedback` 행을 만든다. 원본 댓글이나 과거 분석은 수정하지 않는다. `use_for_personalization`이 활성화된 승인 사례는 향후 분석에서 검색할 수 있다.

## 9. 댓글 관리 조치

시스템은 조치를 추천하지만 파괴적 조치를 자동 실행하지 않는다.

필수 순서:

```text
원본과 현재 상태 불러오기
→ 증거 레코드 생성
→ 조치와 결과를 사용자에게 설명
→ 크리에이터의 명시적 확인
→ 필요한 OAuth 권한 확인
→ 지원되는 YouTube API 호출
→ 성공 또는 실패 기록
→ 감사 이벤트 추가
```

현재 공식 YouTube API와 승인된 권한이 정확한 작업을 지원하는 경우에만 숨김·거절·삭제 요청을 제공한다. 권한이 없다면 조용히 실패하지 않고 점진적 권한 부여를 시작한다.

출처 댓글을 삭제하거나 거절해도 저장된 원본은 삭제하지 않는다. 출처가 나중에 사라지면 `source_deleted_at`을 기록하고 기존 분석과 조치 이력을 보존한다.

## 10. 보안과 개인정보

- 모든 비밀값과 제공자 토큰을 서버에만 보관한다.
- Google 토큰은 데이터베이스와 분리된 서버 암호화 키로 저장 시 암호화한다.
- OAuth `state`와 콜백 출처를 검증한다.
- 최소 권한을 요청하고 점진적 권한 부여를 사용한다.
- Supabase 서비스 역할 키를 브라우저에 노출하지 않는다.
- 외부에 노출된 모든 테넌트 테이블에 RLS를 활성화한다.
- 같은 워크스페이스 접근과 다른 워크스페이스 접근 거부를 테스트한다.
- 유해 댓글 원문, 제공자 토큰, 인증 코드와 API 키를 로그에 남기지 않는다.
- 연결을 해제하면 저장한 토큰을 폐기하거나 삭제하고 동기화를 중단한다.
- 연결 해제만으로 가져온 데이터를 조용히 삭제하지 않는다.
- 별도 확인을 받은 워크스페이스 데이터 삭제는 원본, 분석, 임베딩과 파생 데이터를 제거하고 내용이 없는 최소 삭제 감사 이벤트만 남긴다.
- 법률적 결론을 내리지 않는다.

## 11. 안정성과 오류 처리

댓글 가져오기 및 분석 작업 상태:

```text
pending
running
partially_succeeded
succeeded
failed
```

댓글별 상태를 별도로 기록해 댓글 하나의 실패 때문에 성공한 댓글을 버리지 않는다.

일시적인 네트워크 오류, 제공자 `5xx`와 속도 제한 응답은 지수형 대기를 적용해 최대 3번 재시도한다. 잘못된 요청, 철회된 권한, 없는 권한과 소진된 할당량은 외부 상태가 바뀌기 전까지 자동 반복하지 않는다.

사용자에게 보여주는 상태:

- 연결되지 않음
- 연결됨
- 채널 또는 영상이 비어 있음
- 댓글 사용 중지
- 댓글 가져오기 대기·진행·일부 성공·실패·성공
- 분석 대기·진행·일부 성공·실패·성공
- 만료되거나 철회된 Google 권한
- 댓글 관리 권한 부족
- YouTube 할당량 소진
- OpenAI 속도 제한 또는 스키마 실패
- 재시도 가능한 오류와 재시도 불가능한 오류

분석 멱등성 키는 다음 조합을 사용한다.

```text
raw_comment_id
+ creator_policy_version
+ prompt_version
+ model_version
+ schema_version
```

재분석 후에도 과거 모델 실행 기록을 확인할 수 있어야 한다.

```text
랜딩

```

자동 테스트에서는 Google, YouTube와 OpenAI 응답을 모의 처리한다. 별도의 수동 테스트에서만 크리에이터가 관리하는 실제 채널과 실제 자격 증명을 사용한다.

### 한국어 평가 세트

사람이 검토한 사례를 최소 60개 유지한다.

- 긍정 및 중립 댓글
- 질문
- 건설적인 비판
- 욕설이 있지만 유용한 피드백
- 순수 욕설
- 비꼼과 간접 공격
- 크리에이터 채널에서 친근하게 사용하는 은어
- 한국어 띄어쓰기와 반복 글자 변형
- 광고, 반복과 피싱
- 괴롭힘과 협박
- 판단이 애매한 댓글

평가 데이터는 실제 사용자 댓글과 분리하고 학습에 자동 사용하지 않는다.

## 14. 출시 기준

다음 조건을 충족하기 전에는 첫 수직 슬라이스가 완성된 것으로 보지 않는다.

- 원본 댓글 수정 0건
- 다른 워크스페이스의 원본 또는 RAG 데이터 노출 0건
- 사용자의 명시적 확인 없는 댓글 관리 조치 0건
- 순수 욕설 평가 사례에서 만들어낸 가짜 유용 피드백 0건
- 명백한 위험 평가 사례를 `안전`으로 분류한 결과 0건
- 구조화 응답이 최초 또는 한 번의 재시도 후 런타임 스키마 검증 통과
- 같은 원본을 반복해서 가져왔을 때 중복 원본 댓글 행 0건
- 연결되지 않은 화면에서 가짜 실제 통계 표시 0건
- 실제 채널, 영상과 댓글 20~50개 가져오기 수동 검증
- 대시보드와 Inbox에서 같은 실제 저장 레코드 표시
- `npm test`, `npm run lint`, `npm run build` 통과

Fine-tuning은 의존 기능이나 제공을 약속한 기능이 아니다. 제공자가 Fine-tuning을 지원하고, 동의받은 대표 데이터가 충분하며, 별도로 보관한 한국어 평가 세트에서 공통 기본 모델과 정책·규칙·검색 조합보다 측정 가능한 개선이 입증된 경우에만 공통 Fine-tuned 모델을 다시 검토한다.
