# CommentHawk Codex 가이드 재작성 설계

## 목표

PDF에서 추출한 1~8번 자료를 다른 개발자도 순서대로 읽고 바로 활용할 수 있는 Markdown 가이드로 재작성한다. 설명은 한국어로 작성하고, Codex에 그대로 입력하는 프롬프트만 영어 코드 블록으로 유지한다.

## 기준 문서와 우선순위

내용이 충돌하면 다음 순서를 적용한다.

1. `docs/product-context.md`
2. `docs/CommentHawk_Project_Context_v0.1.pdf`
3. 저장소 루트의 `AGENTS.md` 규칙
4. 이번에 제공된 1~8번 PDF

기존 PDF의 목업 대시보드 우선 지침은 현재 제품 원칙과 충돌하므로 그대로 유지하지 않는다. 개발의 첫 우선순위는 다음 실제 수직 슬라이스다.

```text
YouTube 연결
→ 영상 하나 선택
→ 댓글 20~50개 가져오기
→ AI 분류
→ 원문과 분석 결과를 DB에 분리 저장
→ Comment Inbox에서 실제 데이터 확인
```

## 편집 원칙

- PDF 페이지 제목, 페이지 번호, 머리말과 꼬리말을 제거한다.
- 2번 문서에 중복 삽입된 3번 내용을 제거한다.
- PDF 줄바꿈으로 갈라진 한국어 문장과 영어 단어를 복원한다.
- 같은 요구사항은 가장 관련 있는 문서 한 곳에서만 자세히 설명한다.
- 반복해야 하는 핵심 안전 원칙은 짧게 요약하고 기준 문서를 링크한다.
- 표, 순서 목록, 체크리스트와 코드 블록을 사용해 한눈에 구조를 파악할 수 있게 한다.
- 영어 프롬프트는 복사 가능한 하나의 코드 블록으로 제공한다.
- 목업 데이터, 예시 수치, 연결되지 않은 플랫폼을 실제 기능처럼 표현하지 않는다.
- 유해 댓글 원문은 기본적으로 가리고, AI 결과와 정제 문구로 원문을 덮어쓰지 않는다.
- 삭제·숨김·거절 같은 비가역적 조치는 증거 보존과 사용자 확인 뒤에만 수행한다.

## 문서별 역할

### 1. Codex에 넣기 전에 준비할 자료

제품 기준 문서, 시각 참고자료, 환경 변수 준비 범위와 작업 시작 전 확인 항목을 설명한다. BrandBastion은 품질과 리듬을 참고하는 시각 자료일 뿐 복제 대상이 아님을 명시한다.

### 2. 먼저 설치하면 좋은 Codex용 기능

shadcn 관련 도구와 Next.js 개발 도구를 선택 항목으로 설명한다. 설치 여부를 과장하지 않고, 실제 프로젝트의 패키지 관리자와 현재 Next.js 문서를 먼저 확인하도록 안내한다.

### 3. 실제로 사용할 GitHub 저장소

라이브러리를 용도, 도입 시점, 주의사항으로 정리한다. 전체 저장소나 대시보드 템플릿을 복제하지 않고 필요한 공식 패키지만 사용하도록 설명한다.

### 4. 첫 번째 Codex Ask 모드 프롬프트

저장소와 제품 기준 문서를 읽은 뒤 첫 실제 수직 슬라이스의 구현 계획만 작성하게 하는 영어 프롬프트를 제공한다. 이 단계에서는 파일 수정, 패키지 설치와 구현을 금지한다.

### 5. 승인된 계획 실행용 프롬프트

승인된 계획에 따라 수직 슬라이스의 기반을 구현하게 하는 영어 프롬프트를 제공한다. 기존 UI를 보존하고, 필요한 스키마와 서비스 경계를 만들며, 연결되지 않은 데이터를 실제처럼 표시하지 못하게 한다.

### 6. YouTube 연결과 댓글 가져오기 프롬프트

Google OAuth, 영상 선택, 댓글 20~50개 가져오기, Supabase 저장, 동기화 상태와 오류 처리를 구현하게 하는 영어 프롬프트를 제공한다. 최소 권한, 서버 측 비밀 관리와 검토 우선 조치를 포함한다.

### 7. AI 분류와 Comment Inbox 완성 프롬프트

OpenAI 구조화 출력, 런타임 검증, 원문·분석 결과·정제 문구의 분리 저장, 신뢰도와 수동 검토, 실제 Comment Inbox 표시를 구현하게 하는 영어 프롬프트를 제공한다. Q&A Radar, Signal Digest와 Evidence Vault 확장은 후속 범위로 남긴다.

### 8. 가장 중요한 수정점

시각 참고자료의 안전한 사용법, 랜딩 페이지와 운영 화면의 차이, 데이터·AI·조치 안전 원칙, 실제 개발 순서를 짧은 체크리스트로 정리한다.

## 공통 문서 형식

각 문서는 다음 순서를 따른다.

1. 문서 목적
2. 적용 시점
3. 핵심 내용 또는 준비 체크리스트
4. 필요한 경우 복사용 영어 프롬프트
5. 완료 기준과 다음 문서 링크

## 검증 기준

- 1~8번 제목이 목차와 일치한다.
- PDF 페이지 번호와 반복 제목이 남지 않는다.
- 2번과 3번 사이에 내용 중복이 없다.
- 영어 단어가 PDF 줄바꿈 때문에 중간에서 분리되지 않는다.
- 프롬프트 밖의 설명은 모두 자연스러운 한국어다.
- 개발 순서가 실제 YouTube 수직 슬라이스 우선 원칙과 일치한다.
- 원문 댓글, AI 출력, 정제 문구, 사용자 조치, 증거와 감사 로그의 분리 원칙이 유지된다.
- 비가역적 조치에는 증거 보존과 명시적 사용자 확인이 요구된다.
- `npm run lint`와 `npm run build`가 통과한다.
