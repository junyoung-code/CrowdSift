# CommentHawk Codex 가이드 재작성 설계

## 목표

PDF에서 추출한 1~8번 자료를 다른 개발자도 순서대로 읽고 바로 활용할 수 있는 Markdown 가이드로 재작성한다. 설명은 한국어로 작성하고, Codex에 그대로 입력하는 프롬프트만 영어 코드 블록으로 유지한다.

## 기준 문서와 우선순위

내용이 충돌하면 다음 순서를 적용한다.

1. `docs/product-context.md`
2. `docs/CommentHawk_Project_Context_v0.1.pdf`
3. 저장소 루트의 `AGENTS.md` 규칙
4. 이번에 제공된 1~8번 PDF

기존 PDF의 목업 대시보드 우선 지침은 현재 제품 원칙과 충돌하므로 그대로 유지하지 않는다. 개발의 첫 우선순위는 다음 실제 수직 슬라이스다.

```text
YouTube 연결
→ 영상 하나 선택
→ 댓글 20~50개 가져오기
→ AI 분류
→ 원문과 분석 결과를 DB에 분리 저장
→ Comment Inbox에서 실제 데이터 확인
```

## 편집 원칙

- PDF 페이지 제목, 페이지 번호, 머리말과 꼬리말을 제거한다.
- 2번 문서에 중복 삽입된 3번 내용을 제거한다.
- PDF 줄바꿈으로 갈라진 한국어 문장과 영어 단어를 복원한다.
- 같은 요구사항은 가장 관련 있는 문서 한 곳에서만 자세히 설명한다.
- 반복해야 하는 핵심 안전 원칙은 짧게 요약하고 기준 문서를 링크한다.
- 표, 순서 목록, 체크리스트와 코드 블록을 사용해 한눈에 구조를 파악할 수 있게 한다.
- 영어 프롬프트는 복사 가능한 하나의 코드 블록으로 제공한다.
- 목업 데이터, 예시 수치, 연결되지 않은 플랫폼을 실제 기능처럼 표현하지 않는다.
- 유해 댓글 원문은 기본적으로 가리고, AI 결과와 정제 문구로 원문을 덮어쓰지 않는다.
- 삭제·숨김·거절 같은 비가역적 조치는 증거 보존과 사용자 확인 뒤에만 수행한다.

## 사용자별 AI 개인화와 Fine-tuning 원칙

CommentHawk의 개인화는 모델 하나에 모든 사용자 데이터를 섞는 방식이 아니라, 사용자 또는 워크스페이스별 정책과 수정 이력을 분리하는 방식으로 시작한다. Fine-tuning은 API 호출을 대체하는 별도 실행 방식이 아니며, 학습 작업과 학습된 모델 호출 역시 제공자의 API 또는 자체 호스팅 추론 계층을 통해 수행한다.

개인화는 다음 순서로 발전시킨다.

1. **사용자 설정 기반 개인화**
   - 사용자별 분류 기준, 허용 표현, 스팸 규칙, 민감도와 조치 선호도를 저장한다.
   - 요청 시 해당 사용자 설정과 승인된 예시만 모델 컨텍스트에 전달한다.
   - 사용자 설정은 공통 프롬프트, 원본 댓글과 분리하고 버전을 기록한다.
2. **수정 이력 기반 적응**
   - AI 분류에 대한 사용자의 승인, 거절, 카테고리 수정과 정제 문구 수정을 별도 피드백 레코드로 저장한다.
   - 수정 이력은 다음 추론의 few-shot 예시와 평가 데이터 후보로 사용할 수 있다.
   - 자동 학습 데이터 편입은 금지하고, 사용자의 동의와 데이터 품질 검토를 거친다.
3. **평가 기반 모델 최적화**
   - 대표적인 한국어 댓글 평가 세트로 기본 모델과 개인화 프롬프트의 기준 성능을 먼저 측정한다.
   - 프롬프트와 사용자 설정만으로 목표 성능을 충족하는지 확인한다.
   - 반복되는 분류 실패가 충분한 고품질 정답 데이터로 확인될 때만 fine-tuning 후보로 승격한다.
4. **선택적 Fine-tuning**
   - 학습 세트와 평가 세트를 분리하고, 사용자 동의·삭제 요청·보존 기간을 추적할 수 있는 데이터만 사용한다.
   - 초기에는 사용자마다 별도 모델을 만들지 않고, 검증된 공통 한국어 댓글 분류 모델과 사용자별 설정 계층을 조합한다.
   - 대규모 고객이나 충분한 정답 데이터가 있는 워크스페이스에만 전용 모델을 검토한다.
   - 학습 전후의 정확도, 유해 댓글 누락률, 건설적 피드백 오분류율, 비용과 지연 시간을 같은 평가 세트로 비교한다.
   - 기본 모델보다 개선되지 않거나 안전 기준을 충족하지 못하면 배포하지 않는다.

2026년 7월 현재 OpenAI 공식 문서는 기존 fine-tuning 플랫폼을 축소 중이며 신규 사용자는 접근할 수 없다고 안내한다. 따라서 특정 OpenAI fine-tuning 모델을 제품 전제조건으로 고정하지 않는다. 지원 여부를 구현 시점에 공식 문서로 다시 확인하고, 제공자 교체가 가능한 모델 어댑터와 평가 중심의 데이터 파이프라인을 설계한다.

## 문서별 역할

### 1. Codex에 넣기 전에 준비할 자료

제품 기준 문서, 시각 참고자료, 환경 변수 준비 범위와 작업 시작 전 확인 항목을 설명한다. BrandBastion은 품질과 리듬을 참고하는 시각 자료일 뿐 복제 대상이 아님을 명시한다.

### 2. 먼저 설치하면 좋은 Codex용 기능

shadcn 관련 도구와 Next.js 개발 도구를 선택 항목으로 설명한다. 설치 여부를 과장하지 않고, 실제 프로젝트의 패키지 관리자와 현재 Next.js 문서를 먼저 확인하도록 안내한다.

### 3. 실제로 사용할 GitHub 저장소

라이브러리를 용도, 도입 시점, 주의사항으로 정리한다. 전체 저장소나 대시보드 템플릿을 복제하지 않고 필요한 공식 패키지만 사용하도록 설명한다.

### 4. 첫 번째 Codex Ask 모드 프롬프트

저장소와 제품 기준 문서를 읽은 뒤 첫 실제 수직 슬라이스의 구현 계획만 작성하게 하는 영어 프롬프트를 제공한다. 이 단계에서는 파일 수정, 패키지 설치와 구현을 금지한다.

### 5. 승인된 계획 실행용 프롬프트

승인된 계획에 따라 수직 슬라이스의 기반을 구현하게 하는 영어 프롬프트를 제공한다. 기존 UI를 보존하고, 필요한 스키마와 서비스 경계를 만들며, 연결되지 않은 데이터를 실제처럼 표시하지 못하게 한다.

### 6. YouTube 연결과 댓글 가져오기 프롬프트

Google OAuth, 영상 선택, 댓글 20~50개 가져오기, Supabase 저장, 동기화 상태와 오류 처리를 구현하게 하는 영어 프롬프트를 제공한다. 최소 권한, 서버 측 비밀 관리와 검토 우선 조치를 포함한다.

### 7. AI 분류와 Comment Inbox 완성 프롬프트

구조화 출력, 런타임 검증, 원문·분석 결과·정제 문구의 분리 저장, 신뢰도와 수동 검토, 실제 Comment Inbox 표시를 구현하게 하는 영어 프롬프트를 제공한다. 사용자별 분류 설정과 수정 이력을 별도 저장하고, 향후 평가·few-shot·fine-tuning 데이터로 안전하게 활용할 수 있는 피드백 구조를 포함한다. Q&A Radar, Signal Digest, Evidence Vault와 실제 fine-tuning 작업은 후속 범위로 남긴다.

### 8. 가장 중요한 수정점

시각 참고자료의 안전한 사용법, 랜딩 페이지와 운영 화면의 차이, 데이터·AI·조치 안전 원칙, 사용자별 개인화와 fine-tuning 도입 조건, 실제 개발 순서를 짧은 체크리스트로 정리한다.

## 제품 기준 문서 갱신

재작성 과정에서 `docs/product-context.md`에도 개인화 원칙을 추가한다. 사용자 설정과 수정 이력을 먼저 활용하고, 평가로 개선이 확인될 때만 fine-tuning을 검토한다는 순서를 제품 소스 오브 트루스에 남긴다.

## 공통 문서 형식

각 문서는 다음 순서를 따른다.

1. 문서 목적
2. 적용 시점
3. 핵심 내용 또는 준비 체크리스트
4. 필요한 경우 복사용 영어 프롬프트
5. 완료 기준과 다음 문서 링크

## 검증 기준

- 1~8번 제목이 목차와 일치한다.
- PDF 페이지 번호와 반복 제목이 남지 않는다.
- 2번과 3번 사이에 내용 중복이 없다.
- 영어 단어가 PDF 줄바꿈 때문에 중간에서 분리되지 않는다.
- 프롬프트 밖의 설명은 모두 자연스러운 한국어다.
- 개발 순서가 실제 YouTube 수직 슬라이스 우선 원칙과 일치한다.
- 원문 댓글, AI 출력, 정제 문구, 사용자 조치, 증거와 감사 로그의 분리 원칙이 유지된다.
- 사용자 설정, 사용자 수정 이력, 평가 데이터, 학습 데이터와 모델 버전이 서로 구분된다.
- fine-tuning 없이도 동작하는 기본 경로가 있으며, fine-tuning은 평가를 통과한 선택적 후속 단계로 표현된다.
- 사용자 데이터의 학습 사용에는 명시적 동의, 삭제 가능성, 보존 기간과 테넌트 분리가 요구된다.
- 비가역적 조치에는 증거 보존과 명시적 사용자 확인이 요구된다.
- `npm run lint`와 `npm run build`가 통과한다.
