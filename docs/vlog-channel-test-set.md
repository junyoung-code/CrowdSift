# 브이로그 채널 테스트 세트 v0.1 — OAuth 연결 후 반복 검증용

`docs/test-comment-plan.md`(v0.3, 90개)와 용도가 다르다. 그쪽은 파이프라인이 도는지
보는 묶음이고, 이쪽은 **실제 영상 3개로 확인한 뒤 남은 약점만 골라 찌르는 묶음**이다.

> **여기 적힌 기대 등급도 정답이 아니다.**
> 우리가 「이렇게 나와야 맞다」고 보는 값이다. 결과가 다르면 기준이 틀렸는지 프롬프트가
> 틀렸는지 갈라서 봐야 한다. 정확도 수치로 바로 쓰지 않는다.

> **측정 잡음이 3.3%다.**
> 같은 프롬프트로 두 번 돌려도 90건 중 3건은 등급이 바뀐다. 1~2건 차이는 신호가 아니다.

---

## 왜 이 묶음이 필요한가

실제 영상 3개(정치 논란·사과 영상·개인 브이로그)를 돌리고 남은 것:

| 남은 문제 | 실제로 본 것 |
|---|---|
| **외모 언급을 공격과 구분 못 함** | 「화장 전후 왜케 달라」가 주의로 잡힘. 은어를 아무리 풀어도 안 내려감 |
| **`sensitiveTopics` 가 등급을 올려 버림** | `['외모']`를 켜니 안전하던 댓글이 위험으로 올라감. 프롬프트는 "올리지 않는다"고 적혀 있는데 실제로는 올린다 |
| **짧은 말이 흔들림** | 「좌로로」「ㅋㅋㅋ」「관상...」이 돌릴 때마다 바뀜 |
| **콜드 스타트** | 은어 목록이 비면 칭찬형 비속어가 전부 주의로 쌓임 |
| **타임스탬프 댓글이 그대로 분석됨** | 「15:30」만 적힌 댓글에 API 비용이 나감 |

이 다섯 개를 겨냥한다. 평범한 댓글은 **대조군으로만** 넣는다 — 고치다가 멀쩡한 걸
망가뜨리는지 봐야 하니까.

## 채널 페르소나

### 「집에서 뭐 먹지」

| | |
|---|---|
| **채널** | 자취 4년차의 퇴근 후 요리·집 정리 브이로그 |
| **말투** | 자막 위주, 말수 적음, 담백함 |
| **얼굴** | 나옴. 화장 거의 안 함 |
| **구독자층** | 20~30대 자취생. 댓글이 다정한 편이고 반말·존댓말이 섞임 |

**이 페르소나를 고른 이유는 약점을 자연스럽게 불러오기 때문이다.**

```
얼굴이 나옴        →  외모 댓글이 억지 없이 달림      ← 가장 약한 곳
자취·살림         →  오지랖 댓글 (결혼은? 부모님은?)  ← 무례하지만 악의 없음
요리              →  건설적 비판과 인신공격이 갈림
자막 위주          →  자막 관련 요청 (기존 fixture 와 이어짐)
```

### 영상 — 둘로 나눈다

**소유 채널 가져오기는 최상위 댓글 20~50개로 제한된다**(`comment_import_jobs_source_contract`).
이 묶음은 최상위가 58개라 영상 하나에 다 올릴 수 없다. 답글은 상한에 세지 않으므로
(`topLevelLimit`) 부모 개수만 맞추면 된다.

| | 영상 1 | 영상 2 |
|---|---|---|
| **제목** | `퇴근하고 30분, 자취 4년차 냉장고 털이` | `자취방 대청소, 6개월 묵은 베란다` |
| **무리** | A 외모 12 · B 은어 8 · C 짧은말 8 · E 옹호 6 | D 타임스탬프 5 · F 오지랖 6 · G 비판 5 · H 악플 5 · I 스팸 3 |
| **최상위** | 34 | 24 |
| **답글** | 4 (J01~J04 → A05) + 3 (K, 펴진 답글) | 4 (J05~J08 → G01) |
| **합계** | **41** | **28** |

**E(옹호)가 영상 1에 있는 이유**는 A05 「요즘 살찌셨네요」를 가리키기 때문이다.
E01 「밑에 살쪘다는 사람 뭐임?」이 다른 영상에 있으면 가리킬 대상이 없다.

**제목은 대충 정하면 안 된다.** `videoTitle`이 모델 입력에 그대로 들어간다. 「냉장고
털이」가 있어야 「저 계란 상한 거 아니에요?」가 공격이 아니라 걱정으로 읽힌다.

영상 내용 자체는 판단에 안 들어간다. 화면에 뭐가 찍혔는지 우리 시스템은 모른다.
길이는 2분이어도 된다. 둘 다 **일부 공개(링크 있는 사람만)** 로 올린다.

## 게시 전 확인

1. **일부 공개로 올린다.** 거친 댓글이 완전 공개 영상에 달리면 계정 제재 위험이 있다.
2. **부계정을 셋 만든다. 본계정으로는 댓글을 달지 않는다.**
   본계정으로 달면 `author_channel_id`가 채널 주인이 되어 전부 `delete_eligible`로
   뜬다. 「채널 주인 댓글은 거른다」를 나중에 넣으면 세트가 통째로 사라진다.
   셋인 이유는 답글 스레드 때문이다. 부모·찬성·반대가 같은 사람이면 대화가 아니다.

   | 댓글 | 계정 |
   |---|---|
   | A05 「요즘 살찌셨네요」 | 부계정 1 |
   | ↳ J01 J03 | 부계정 2 |
   | ↳ J02 J04 | 부계정 3 |
   | G01 「자막 너무 작아서 …」 | 부계정 2 |
   | ↳ J05 J07 | 부계정 1 |
   | ↳ J06 J08 | 부계정 3 |
   | 나머지 | 아무 부계정이나, 골고루 |

3. **새 계정은 만들자마자 대량으로 달면 보류된다.**
   계정마다 아무 영상에 댓글 두어 개 달아 두고 하루쯤 묵힌다. 그리고 한 계정으로
   연속 20개 이상 달지 않는다.
4. **위험군은 일부러 약하게 썼다.**
   유튜브가 먼저 지우면 우리 시스템까지 오지도 않는다. 세게 쓸수록 측정이 안 된다.
5. **표 순서대로 올린다.** `↳`는 지정된 댓글의 답글이다.
6. **게시 후 시크릿 창으로 개수를 센다.** 영상 1은 41개, 영상 2는 28개.
   모자라면 **어느 번호가 사라졌는지 적어 둔다.** 나중에 누락과 오분류를 갈라야 한다.
   H05 「어디 사는지 다 알아냈다」가 가장 먼저 지워질 후보다.

> 남는다.
>
> ```
> 6~9번     입력칸에 칩이 떠 있으면 지우고 올린다   →  원문에 @ 없음   대조군

>

> 넣기도 해서, 버튼 위치만으로는 칩의 유무를 정할 수 없다. 화면에 칩이 보이는지로 판단한다.
>
> 칩을 지워도 **부모는 바뀌지 않는다.** 몇 단을 눌러 들어가든 저장되는 `parentId`는 언제나
> 최상위(5번)다. 부모는 어느 스레드에 속했는지로 정해지지 멘션 텍스트로 정해지지 않는다.
>
> 그래서 두 무리는 데이터상 부모가 같고 원문의 `@` 유무만 다르다. 그 하나만 달라야 결과를
> 보고 원인을 짚을 수 있다. 6~9번에도 @가 남으면 무엇 때문인지 못 가른다.
>
> 7번이 6번에 대한 반박이라 6번에 달고 싶어지지만, 칩만 지우면 어디에 달든 상관없다.
>
> 칩은 유튜브가 자동으로 넣는다. **직접 타이핑하지 않는다.**

> 36번 「밑에 살쪘다는 사람」의 **「밑에」는 신경 쓰지 않아도 된다.** 유튜브 정렬에 따라

## A. 외모 — 언급인가 공격인가 (12개)

**가장 약한 곳.** 지금은 외모가 나오면 공격이 아니어도 주의로 간다.

여기서 봐야 할 것은 등급 하나가 아니다. **왜 잡혔는지**를 봐야 한다. 판단 과정을 펼쳐서

## K. 펴진 답글 — 부모가 실제 상대와 다를 때 (3개)

**유튜브에는 3단 대댓글이 없다.** 답글에 답글을 달면 같은 층으로 펴지고 `@사용자명`이
앞에 붙는다. API 도 `parentId`를 **최상위 댓글**로 준다. 우리가 그렇게 저장하는 것은
버그가 아니라 유튜브가 그렇게 주기 때문이다.

문제는 그다음이다. 모델이 받는 부모가 **실제로 답한 상대가 아니다.**

실제 수집 데이터에서 이미 나온 모양이다. 12개짜리 스레드 하나에서 답글 11개가 전부
같은 최상위를 부모로 갖는데, 그중 몇 개는 서로 `@`로 대화하고 있었다.

```
정치고 뭐고 한로로 좋아하는 사람들 진심 단체로 약빤놈들 같       ← 모두의 부모
  ├ 가창력도 좋고 성량도 좋고 기교도 뛰어난데요??              (옹호)
  └ @th1s_and_that근데 노래는 진짜 ㅈㄴ못하더라                (옹호자에게 반박)
```

아래 댓글은 **옹호자를 반박한 것**인데, 모델은 부모로 「팬들 약빤놈들」을 받는다.
악플러에게 동조하는 말처럼 읽힌다. **방향이 뒤집힌다.**

| # | 어디에 답글 | 댓글 | 실제 뜻 | 모델이 받는 부모 |
|---|---|---|---|---|
| K01 | J03 (옹호) | @… 님이야말로 오지랖이신 듯 | 옹호자를 공격 | A05 「요즘 살찌셨네요」 |
| K02 | J01 (비판) | @… 맞말 | 악플러 비판에 동의 | A05 |
| K03 | K01 | @… 그쪽이 더 심한데요 | K01 을 되받아침 | A05 |

**정답 등급을 정하지 않는다.** 여기서 보려는 것은 등급이 맞았는지가 아니라 **부모가
틀렸을 때 판단이 얼마나 흔들리는지**다. 볼 것은 셋이다.

1. K01 이 「악플러를 나무라는 말」로 읽히는가. 그렇다면 부모를 그대로 믿고 있다는 뜻이다.
2. K02 「맞말」이 방향을 잡는가. 두 글자짜리라 부모가 전부다.
3. `@사용자명` 이 원문에 그대로 남아 모델에 들어간다. 이것이 판단을 흔드는지.

고칠 방법이 있다면 `@사용자명`으로 같은 스레드 안에서 상대를 찾아 진짜 부모로 잇는
것이다. **지금은 그 코드가 없다.** 먼저 얼마나 틀리는지 재고 나서 정한다.

## 가져오기와 분석 순서

댓글은 69개를 한 번에 다 달아도 된다. **순서를 지켜야 하는 것은 게시가 아니라 분석이다.**

```
1. 영상 2개를 각각 수동으로 가져온다   상한은 둘 다 50 으로 잡는다
2. 은어 목록을 비운다                 ← 이걸 빠뜨리면 B 무리 측정이 날아간다
3. 69개 전체 분석                    A·C·D~K 결과 + B 콜드 스타트
4. B 무리를 「칭찬으로 등록」 후 재분석    몇 개가 내려가는지
5. C 무리만 두 번 더                  흔들림 측정
```

**채널 동기화는 켜지 않는다.** 그것은 날짜로 긁어서 예전 테스트 영상까지 끌고 온다.
이 묶음이 끝날 때까지는 영상을 골라 가져오는 수동 경로만 쓴다.

2번에 UI가 없다. 설정 화면의 「허용할 표현」은 `creator_policies`로 가고
`classification_profiles.allowed_slang`과 이어져 있지 않다. 지금은 직접 비워야 한다.
