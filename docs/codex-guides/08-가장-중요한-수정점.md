# 가장 중요한 수정점

## 문서 목적

1~7번을 실행하는 동안 제품 방향이 다시 흐트러지지 않도록 반드시 지켜야 할 기준을 한곳에 모은다.

## 1. 시각 참고자료는 복제 대상이 아니다

다음과 같은 지시는 사용하지 않는다.

```text
Copy BrandBastion almost exactly.
```

대신 품질과 분위기는 참고하되 결과물은 독창적이어야 한다고 명시한다.

```text
Use the reference only to understand visual quality, section rhythm, typography scale,
spacing density, blue-and-white enterprise SaaS tone, product-preview composition,
and restrained motion.

Create original branding, copy, components, illustrations, and layouts. Do not copy
assets, source code, logos, customer claims, testimonials, or exact geometry.
```

랜딩 페이지와 제품 화면도 같은 밀도로 만들지 않는다.

- 랜딩 페이지: 크고 명확하며 제품 가치를 설명하는 흐름
- Comment Inbox: 조용하고 촘촘하며 반복 검토에 적합한 흐름

## 2. 연결되지 않은 데이터를 실제처럼 보이지 않는다

- 예시 댓글과 수치는 테스트 또는 데모임을 명확히 표시한다.
- 실제 API가 연결되지 않았다면 연결 완료, 동기화 완료 또는 분석 완료처럼 표현하지 않는다.
- Instagram, TikTok, 결제와 다른 후속 기능을 이미 지원하는 것처럼 표시하지 않는다.
- 프로덕션 화면의 실제 데이터 경로에 fixture를 섞지 않는다.

## 3. 데이터는 역할별로 분리한다

다음 데이터는 서로 덮어쓰거나 한 필드에 섞지 않는다.

- YouTube 원본 댓글과 출처 메타데이터
- 결정적 규칙 검사 결과
- AI 분석 결과
- 정제된 피드백
- 크리에이터 정책과 금지어·허용어
- 크리에이터 승인·거절·수정 이력
- 사용자 조치 요청과 실행 결과
- 증거 레코드
- 프롬프트·스키마·모델 버전
- 평가 데이터와 동의받은 학습 후보
- 감사 로그

원본 댓글은 항상 보존하고, 정제된 문장으로 교체하지 않는다.

## 4. 개인화는 여섯 계층으로 구현한다

1. 공통 OpenAI 모델이 한국어 댓글의 의미와 유형을 분석한다.
2. 크리에이터별 정책이 금지어, 허용어, 민감도와 원하는 조치를 제공한다.
3. 크리에이터별 피드백 RAG가 같은 크리에이터의 비슷한 과거 판단만 가져온다.
4. 규칙 엔진이 정확한 금지어, 반복 광고와 URL 같은 신호를 검사한다.
5. AI는 조치를 추천하고 사용자가 실제 실행을 확인한다.
6. 충분한 한국어 평가 데이터가 쌓인 경우에만 공통 Fine-tuning을 검토한다.

금지어는 강한 신호지만 자동 판결은 아니다. “미쳤다”처럼 칭찬과 공격에 모두 쓰일 수 있는 표현은 문맥, 허용 예외와 과거 피드백을 함께 판단한다.

## 5. Fine-tuning은 첫 구현이 아니다

Fine-tuning 전에 다음 조건을 모두 충족해야 한다.

- 기본 모델과 크리에이터 정책만으로 만든 성능 기준이 있다.
- 대표적인 한국어 댓글 평가 세트가 있다.
- 반복되는 실패 유형이 확인됐다.
- 사용자가 학습 사용에 동의한 고품질 정답 데이터가 충분하다.
- 학습 세트와 평가 세트가 분리돼 있다.
- 개인정보와 작성자 식별 정보가 필요한 수준으로 제거됐다.
- 삭제 요청, 보존 기간, 데이터 출처와 버전을 추적할 수 있다.
- 학습 후 정확도와 안전성이 기본 방식보다 개선됐다.

초기에는 크리에이터마다 대형 모델을 만들지 않는다. 하나의 공통 모델이 크리에이터별 정책을 따르도록 하고, 개인 취향은 DB와 피드백 검색 계층에서 관리한다.

## 6. AI가 사용자를 대신해 비가역적 결정을 내리지 않는다

- 유해 원문은 기본적으로 가린다.
- 건설적인 비판은 자동으로 삭제하지 않는다.
- 낮은 신뢰도와 고위험 댓글은 수동 검토로 보낸다.
- 숨김·거절·삭제 전 원문과 필요한 증거를 보존한다.
- 실제 조치 전 사용자의 명시적 확인을 받는다.
- 요청자, 시각, 결과와 오류를 감사 로그에 남긴다.
- 범죄 성립, 승소 가능성이나 자동 법적 조치를 판단하지 않는다.

## 7. 개발 순서를 바꾸지 않는다

```text
기준 문서와 저장소 확인
→ 첫 실제 수직 슬라이스 계획
→ 최소 기반과 데이터 경계
→ 실제 YouTube 연결
→ 영상 하나 선택
→ 댓글 20~50개 가져오기
→ AI 분류와 크리에이터별 개인화
→ 원문과 분석 결과 분리 저장
→ 실제 Comment Inbox 검토
→ 평가 데이터 축적
→ Q&A Radar·Signal Digest·Evidence Vault 확장
→ 성능 개선이 입증된 경우 공통 Fine-tuning 검토
```

결제, 다중 플랫폼, 전체 통계 대시보드와 모바일 앱은 첫 실제 수직 슬라이스보다 앞서지 않는다.

- [ ] 크리에이터 정책과 과거 피드백이 테넌트별로 격리됐다.
- [ ] 규칙 결과와 AI 판단 근거를 추적할 수 있다.
- [ ] 유해 원문이 기본적으로 가려져 있다.
- [ ] 비가역적 조치에 사용자 확인이 필요하다.
- [ ] Fine-tuning 없이도 전체 흐름이 동작한다.
