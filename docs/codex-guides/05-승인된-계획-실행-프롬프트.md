# 승인된 계획 실행 프롬프트

## 문서 목적

4번에서 승인한 계획 중 실제 연동을 받쳐 줄 최소 기반을 구현한다. 현재 UI를 보존하면서 데이터 경계, 서비스 인터페이스와 정직한 화면 상태를 만든다.

## 적용 시점

Codex가 제시한 계획에서 범위, 데이터 구조, 보안과 검증 방법을 검토하고 명시적으로 승인한 뒤 같은 작업에서 사용한다.

## 복사용 영문 프롬프트

```text
I approve the implementation plan for the CrowdSift real vertical slice.

Implement the approved foundation milestone now. Re-inspect the repository first and report any material conflict before changing files.

Use docs/product-context.md and AGENTS.md as the source of truth. Preserve the existing visual language and working behavior. Read the relevant Next.js 16 documentation in node_modules/next/dist/docs before using framework-specific APIs.

This milestone must prepare the repository for:

- YouTube account connection
- selecting one video
- importing 20-50 comments
- AI classification
- creator-specific policies and feedback retrieval
- separate persistence of raw and derived data
- real Comment Inbox results

Implement only the approved foundation required by those capabilities:

1. Define focused domain types and service interfaces for creator accounts, channels, videos, raw comments, analyses, sanitized feedback, creator policies, phrase rules, creator feedback, moderation actions, evidence, model runs, and audit records.
2. Add database migrations and Row Level Security policies if database work is part of the approved milestone. Keep every tenant-owned row scoped by creator or workspace identity.
3. Keep raw comments immutable. Store analyses and sanitized feedback in separate records linked to the source comment.
4. Keep creator preferences, phrase rules, correction history, evaluation items, training-consent state, model versions, moderation actions, evidence, and audit logs structurally separate.
5. Add repository or service boundaries so external APIs are not called directly from UI components.
6. Keep secrets server-side and document variable names only in .env.example.
7. Create truthful disconnected, empty, loading, success, and error states. Do not show fixtures, sample metrics, or placeholder comments as connected data.
8. If fixtures are needed for unit tests or isolated component development, label them clearly and keep them outside production data paths.
9. Keep harmful original text hidden by default and require an explicit warning interaction to reveal it.
10. Require explicit confirmation before any hide, reject, or delete action. Do not implement automatic destructive moderation.

Do not implement unrelated dashboards, billing, multi-platform support, Q&A Radar, Signal Digest, production fine-tuning, or a large design rewrite.

Use the existing package manager and scripts. Add the smallest necessary dependency set only after verifying that each package is required. Update package-lock.json whenever package.json changes.

Add tests for the implemented domain boundaries, tenant isolation, raw-versus-derived separation, truthful empty/disconnected states, and confirmation requirements. Run:

- npm test
- npm run lint
- npm run build

At completion, report:

1. Files changed
2. Data and service boundaries created
3. Migrations and policies added
4. Dependencies added and why
5. Commands run and their results
6. Credentials or external setup still required
7. The exact next milestone from the approved plan
```
