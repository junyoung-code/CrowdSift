# 먼저 설치하면 좋은 Codex용 기능

## 문서 목적

Codex가 프로젝트 상태와 공식 컴포넌트 사용법을 확인하는 데 도움을 주는 선택적 도구를 정리한다. 이 도구들은 제품 런타임 의존성이 아니며, 설치하지 않아도 CommentHawk를 개발할 수 있다.

## 설치 전 원칙

- 현재 저장소는 `package-lock.json`을 사용하므로 프로젝트 명령은 `npm`을 기준으로 한다.
- 설치 명령과 설정 형식은 바뀔 수 있으므로 실행 직전에 해당 도구의 공식 문서를 확인한다.
- 전역 Codex 설정과 프로젝트 패키지를 구분한다.
- 도구가 설치됐다고 가정하지 말고 실제 설정과 연결 상태를 확인한다.
- 새 도구를 추가하기 전에 기존 기능으로 해결할 수 있는지 판단한다.

## 선택적으로 검토할 도구

### shadcn 관련 Skill 또는 MCP

shadcn/ui를 실제로 도입할 때 컴포넌트 검색, 설치 상태 확인과 올바른 조합에 도움을 줄 수 있다. CommentHawk에는 현재 shadcn/ui가 설치되어 있지 않으므로, 도구를 추가하는 것과 UI 라이브러리를 프로젝트에 도입하는 것은 별도 결정이다.

### Next.js 개발 도구

실행 중인 개발 서버의 라우트, 빌드 오류와 런타임 로그를 Codex가 확인하는 데 도움을 줄 수 있다. 이 저장소는 Next.js 16을 사용하므로 코드를 수정하기 전 `node_modules/next/dist/docs/`에서 관련 문서를 먼저 확인한다.

### 브라우저 테스트 도구

실제 화면과 반응형 동작을 검증할 때 사용한다. 설치되지 않은 Playwright를 문서만 보고 바로 추가하지 않고, 승인된 테스트 범위와 기존 Vitest 테스트를 확인한 뒤 결정한다.

## 설정 시 주의사항

MCP 같은 전역 Codex 도구는 일반적으로 사용자 Codex 설정에 등록되며 프로젝트 소스 코드와 별개다. 설정을 바꾸면 Codex 재시작이나 새 작업이 필요할 수 있다. 프로젝트 저장소에는 개인 경로, 토큰이나 비밀값을 기록하지 않는다.

## 완료 기준

- [ ] 도구가 필수인지 선택 사항인지 구분했다.
- [ ] 공식 설치 문서를 현재 시점에 다시 확인했다.
- [ ] 프로젝트 패키지와 전역 Codex 설정을 혼동하지 않았다.
- [ ] 설치되지 않은 기능을 사용할 수 있다고 문서에 표현하지 않았다.
