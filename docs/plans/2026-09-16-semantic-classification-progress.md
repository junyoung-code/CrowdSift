# 의미 분석 분류 리팩터링 — 구현 및 검증 체크리스트

2026-09-18 업데이트. **새 구조 구현과 로컬 검증 완료. 개인 검수 등급과 실제 API 1회 비교 완료. 정식 출시 품질 평가는 미완료.** 변경은 작업 디렉터리에 저장했으며 커밋·원격 DB 적용·배포는 하지 않았다.

## 확정 정책

- 부정적 평가·불만·직설적 취향 자체는 harm이 아니다.
- 의미 복원 불가만 HOLD. 낮은 confidence, API 오류, 출력 검증 실패는 HOLD가 아니다.
- 관련 공격 없음 SAFE → 공격 제거 후 잔존 claim 있음 CAUTION → 없음 RISK.
- 위협도 분리 가능한 피드백이 남으면 CAUTION. severity/criticalHarm은 등급을 덮어쓰지 않는다.
- 확인된 타인 대상 공격과 스팸은 별도 신호. 타인 공격이 있는 SAFE의 원문도 보호한다.
- 잔존 가치는 검증된 claim ID 목록에서 코드로 계산한다.
- CAUTION 재작성은 독립 검증을 통과한 것만 노출한다. 실패 시 한 번 수정하고 재탈락하면 실패 상태를 표시한다.
- 모델 기본값 없음. 실제 정확도 목표와 fixture/코드 검증은 별개다.

## 남은 실제 품질 평가 — 아직 완료로 표시하지 않음

- [ ] 사람이 검수한 SAFE·CAUTION·RISK 각 100건과 HOLD 30건 이상 확보
- [ ] 일부 사례에 meaningClear·target·feedback claim·harm·잔존 claim 정답 작성
- [ ] claim의 다른 표현 대응 및 재작성 정보/강도 보존 검수
- [ ] 후보 모델/추론 설정으로 동일 holdout을 3회 live 평가
- [ ] 세 등급 정확도 >95%, CAUTION/RISK recall ≥95%, 명확한 정상→RISK/순수 공격→SAFE 회귀 오류 0건 확인
- [ ] 측정 결과를 근거로 모델 선택 및 운영 설정 승인
- [ ] 배포 환경에 migration 적용 및 운영 전환

개인 검수 등급과 실제 모델의 개발용 1회 비교는 아래와 같이 수행했다. 운영 모델 선택, 정식 3회 평가, 95% 달성, 원격 배포는 미완료다. 사람이 해야 할 중간 분석 검수를 자동으로 체크하지 않았다.
