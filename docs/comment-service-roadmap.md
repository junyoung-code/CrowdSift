## 1차 핵심 페르소나

### 악플을 피하고 싶지만 피드백은 놓치고 싶지 않은 성장기 1인 크리에이터

- 유튜브를 본업 또는 준본업으로 운영한다.
- 댓글 관리 담당자나 매니저가 없다.
- 콘텐츠 개선을 위해 댓글을 직접 확인해야 한다.
- 인신공격이나 조롱 댓글을 읽으면 촬영·편집 의욕이 크게 떨어진다.
- 댓글을 아예 끄면 시청자의 요구와 콘텐츠 아이디어를 놓칠까 봐 걱정한다.
- 거친 표현 속에 실제 피드백이 있다면, 표현은 제거하고 내용만 받고 싶어 한다.
- 모든 댓글을 직접 읽기보다 중요한 의견과 질문만 요약해서 확인하고 싶어 한다.

이 페르소나의 핵심 욕구는 단순히 **"악플 삭제"**가 아니다.

> **상처받지 않으면서도 시청자의 반응을 이용해 콘텐츠를 개선하고 싶다.**

이 문장이 서비스의 중심이 되어야 한다.

### 페르소나: 성장기 유튜버 지민

- 구독자: 5,000~10만 명
- 업로드 빈도: 주 1~3회
- 운영 형태: 기획·촬영·편집·댓글 관리를 대부분 혼자 수행
- 댓글 수: 영상당 수십~수천 개
- 현재 행동: 업로드 직후 댓글을 반복해서 확인함
- 문제: 긍정 댓글보다 악성 댓글 하나를 오래 기억함
- 갈등: 댓글을 끊고 싶지만, 영상 주제와 개선점을 찾기 위해 계속 확인함
- 현재 해결 방식: 댓글을 안 보려고 하거나 지인에게 먼저 확인해달라고 요청함
- 원하는 결과: 원문은 보지 않고, 개선 의견·질문·시청자 반응만 정리해서 받음

# 안전 / 주의 / 위험 댓글 분류 기준 v0.1

> **목적:** 악성 댓글에 취약한 크리에이터가 공격적인 원문을 직접 읽지 않으면서도, 콘텐츠 개선에 필요한 피드백과 질문을 확인할 수 있도록 댓글의 노출 방식을 결정한다.

> **핵심 원칙:** 댓글 작성자의 선악이나 법적 위법성을 판단하는 것이 아니라, 크리에이터에게 원문을 어떻게 보여줄지 판단한다.

## 1. 분류 기준 한눈에 보기

### 🟢 안전

**원문을 그대로 보여줘도 되는 댓글**

- 공격적 표현이 없다.
- 콘텐츠나 수정 가능한 행동을 대상으로 한다.
- 일반적인 의견, 질문, 요청, 비판에 해당한다.
- 크리에이터가 원문을 읽어도 정서적 피해가 크지 않다.

**처리 방식** — 원문 표시 / 피드백·질문·긍정 반응 등으로 추가 분류 / 주요 의견 요약에 포함

### 🟡 주의

**원문은 숨기고, 유용한 의미만 순화해서 전달할 댓글**

- 욕설, 비속어, 비꼼, 조롱이 포함되어 있다.
- 표현은 공격적이지만 콘텐츠와 관련된 의견이 있다.
- 심각한 인격 공격, 협박, 성희롱, 스토킹은 없다.
- 공격적 표현을 제거하면 실행 가능한 피드백을 추출할 수 있다.

**처리 방식** — 원문 기본 숨김 / 욕설과 조롱 제거 / 실행 가능한 피드백만 중립적으로 재작성 / 의미 없는 비난은 개별 전달하지 않고 통계로만 집계

### 🔴 위험

**원문과 공격의 존재를 기본적으로 노출하지 않을 댓글**

- 크리에이터의 인격이나 존재 자체를 공격한다.
- 외모, 신체, 가족, 사생활, 정체성을 공격한다.
- 성희롱, 혐오 표현, 협박, 스토킹이 포함되어 있다.
- 죽음이나 자해를 유도한다.
- 개인정보나 실제 위치를 노출한다.
- 실제 콘텐츠와 관계없는 심각한 개인 공격이다.

**처리 방식** — 원문 기본 숨김 / 일반 댓글 요약에서 제외 / 삭제·차단·신고 검토 / 원문과 작성자 정보를 증거용으로 별도 보관 / 협박·스토킹·개인정보 노출은 즉시 알림

## 2. 안전 댓글 기준

크리에이터가 댓글 원문을 직접 읽어도 정서적 피해가 크지 않은 댓글이다.

비판적인 내용이더라도 콘텐츠, 편집, 음향, 설명 방식처럼 **수정 가능한 대상을 구체적으로 지적한다면 안전**으로 분류한다.

**포함 기준** — 욕설이나 조롱이 없다 / 크리에이터의 인격을 공격하지 않는다 / 콘텐츠나 행동에 관한 의견이다 / 일반적인 취향과 부정적 감상을 표현한다 / 질문이나 요청이 포함되어 있다 / 구체적인 개선 의견이 있다

**예시**

- 영상이 조금 길어서 중간에 집중력이 떨어졌어요.
- 편집 템포를 조금 더 빠르게 해주세요.
- 마이크 소리가 작게 들립니다.
- 이번 영상은 제 취향은 아니었습니다.
- 이 주제로 후속 영상을 만들어주실 수 있나요?
- 설명이 조금 어려웠습니다. 예시를 추가하면 좋을 것 같아요.
- 이전 영상이 더 재미있었어요.
- 재미없다.
- 오늘 얼굴이 피곤해 보여요.

## 3. 주의 댓글 기준

욕설, 비꼼, 조롱처럼 공격적인 표현이 포함되어 원문 노출은 적절하지 않지만, 심각한 개인 공격이나 위협까지는 아닌 댓글이다.

댓글 안에 콘텐츠 개선에 사용할 정보가 있다면 **표현을 제거하고 내용만 전달한다.**

**포함 기준** — 가벼운 욕설이나 비속어가 포함되어 있다 / 비꼬거나 무시하는 말투를 사용한다 / 콘텐츠나 제작 능력을 거칠게 비판한다 / 공격적인 표현 안에 수정 가능한 의견이 있다 / 직접적인 인격 공격, 협박, 성희롱, 스토킹은 없다

### 자연스러운 말투와 문장부호 사용 기준

순화된 댓글은 모든 문장을 `~요.`로 동일하게 끝내지 않는다. 실제 시청자가 작성한 것처럼 문장의 분위기에 따라 말끝, 문장부호, 이모티콘을 자연스럽게 변화시킨다.

**사용할 수 있는 표현**

- `~하면 더 좋을 것 같아요.`
- `~하면 더 재밌을 것 같아요!`
- `다음에는 ~도 보고 싶어요 :)`
- `~부분은 조금 아쉬웠어요..`
- `~해주시면 더 보기 편할 것 같아요!`
- `~도 한 번 해주시면 좋겠어요ㅎㅎ`
- `~해주시면 좋을 것 같아요 ^^`
- `다음 영상에서는 ~도 기대할게요!`

**사용 가능한 문장부호·이모티콘** — `.` `!` `..` `:)` `^^` `ㅎㅎ`

**사용 원칙**

- 모든 댓글에 이모티콘을 넣지 않는다.
- 한 문장에는 문장부호나 이모티콘을 최대 한 종류만 사용한다.
- 같은 이모티콘을 반복해서 사용하지 않는다.
- 긍정적인 제안이나 요청에는 `!`, `:)`, `^^`, `ㅎㅎ`를 사용할 수 있다.
- 아쉬움을 표현하는 문장에는 `..`를 제한적으로 사용할 수 있다.
- 심각하거나 민감한 내용에는 이모티콘을 사용하지 않는다.
- 원문에 없는 친밀감이나 과도한 긍정 감정을 추가하지 않는다.
- `🥰`, `❤️`, `ㅋㅋㅋㅋ`, `ㅠㅠ`처럼 감정이 강한 표현은 기본적으로 사용하지 않는다.
- 자연스럽지 않다면 이모티콘 없이 작성한다.

**권장 사용 비율** — 일반적인 문장 약 50% / 문장부호 변화 약 30% / 가벼운 표현 약 20%

비율은 절대적인 규칙이 아니라, 모든 순화 댓글이 같은 말투로 보이지 않게 하기 위한 기준이다.

### 순화 예시

| 원문 | 순화된 댓글 |
| --- | --- |
| 편집 개느리네. | 편집 템포가 조금 더 빠르면 더 재밌을 것 같아요! |
| 말 너무 답답하게 한다. | 설명을 조금 더 빠르고 간결하게 해주시면 좋을 것 같아요. |
| 또 똑같은 콘텐츠네. 진짜 질린다. | 다음에는 새로운 콘텐츠도 보고 싶어요 :) |
| 썸네일 낚시 좀 그만해라. | 썸네일과 영상 내용이 조금 더 잘 맞으면 좋을 것 같아요.. |
| 영상이 왜 이렇게 쓸데없이 길어. | 영상 길이가 조금 짧으면 더 집중해서 볼 수 있을 것 같아요! |
| 자막 크기 실화냐? 눈 빠지겠다. | 자막을 조금 더 크게 해주시면 보기 편할 것 같아요! |
| 맨날 같은 말만 반복하네. | 반복되는 설명을 조금 줄이면 영상이 더 깔끔할 것 같아요. |

### 부자연스러운 예시

**이모티콘을 과도하게 사용하지 않는다**

- 부적절: `편집을 조금 더 빠르게 해주시면 정말 좋을 것 같아요!! ^^ :)`
- 권장: `편집 템포가 조금 더 빠르면 재밌을 것 같아요!`

**원문에 없는 호감을 만들지 않는다**

원문이 `또 똑같은 콘텐츠네.` 일 때

- 부적절: `항상 영상 너무 잘 보고 있어요! 다음에는 새로운 콘텐츠도 부탁드려요 :)`
- 권장: `다음에는 새로운 콘텐츠도 보고 싶어요 :)`

원문에 `항상 잘 보고 있다`는 내용이 없으므로 임의로 추가하지 않는다.

**심각한 의견을 장난스럽게 바꾸지 않는다**

원문이 `목소리가 너무 작아서 무슨 말인지 하나도 모르겠다.` 일 때

- 부적절: `목소리 좀 키워주세요ㅎㅎ`
- 권장: `목소리 음량을 조금 높여주시면 더 잘 들릴 것 같아요.`

`ㅎㅎ`를 붙이면 불편의 강도가 지나치게 가볍게 변할 수 있다.

### AI 순화 지침

> 댓글의 욕설, 비꼼, 조롱, 공격적인 표현을 제거하고, 실제 시청자가 크리에이터에게 직접 예의 있게 작성한 것처럼 자연스러운 한국어 댓글로 다시 작성한다. 원문의 핵심 피드백은 유지하되 원문에 없는 칭찬, 호감, 구체적인 해결책은 추가하지 않는다. 모든 문장을 동일한 말투로 작성하지 말고, 문맥에 따라 `.`, `!`, `..`, `:)`, `^^`, `ㅎㅎ` 중 하나를 제한적으로 사용할 수 있다. 이모티콘이나 특수한 문장부호는 자연스러운 경우에만 사용하고, 한 문장에 하나를 초과하지 않는다. 민감하거나 심각한 내용에는 이모티콘을 사용하지 않는다. 구체적인 개선 정보가 없다면 순화된 댓글을 생성하지 않는다.

`tone_variant`는 세 가지로 둔다.

- `neutral`: 차분하고 일반적인 말투
- `friendly`: `!`, `:)`, `^^` 등을 가볍게 사용
- `soft_disappointment`: 아쉬움을 부드럽게 표현하는 말투

핵심은 랜덤으로 이모티콘을 붙이는 것이 아니라, **원문의 내용과 감정에 맞는 자연스러운 시청자 말투를 선택하는 것**이다.

## 4. 위험 댓글 기준

크리에이터 개인의 인격, 외모, 가족, 사생활, 정체성 또는 안전을 공격하는 댓글이다. 실제 피해로 이어질 수 있는 협박, 성희롱, 스토킹, 개인정보 노출도 위험에 포함한다.

**포함 기준** — 다음 중 하나라도 포함되면 위험으로 우선 분류한다.

- 인격이나 존재 자체에 대한 공격
- 외모·신체에 대한 모욕
- 가족이나 지인에 대한 공격
- 성적인 대상화 또는 성희롱
- 죽음이나 자해 유도
- 직접적이거나 암시적인 협박
- 주소·전화번호·실제 위치 등 개인정보 노출
- 지속적인 스토킹 또는 반복 괴롭힘
- 정체성을 대상으로 한 혐오 표현
- 콘텐츠와 관계없는 심각한 개인 공격

**피드백이 함께 있는 위험 댓글**

`넌 진짜 멍청한 것 같고 설명도 너무 길다.` → 위험도 위험 / 원문 숨김 / 피드백 있음 / 추출 내용은 설명을 더 간결하게 해달라는 의견.

위험 댓글에 피드백이 포함되어 있어도 **위험 등급은 낮추지 않는다.**

## 5. 분류 우선순위

댓글에 여러 요소가 함께 있으면 가장 높은 위험도를 적용한다.

> **위험 요소가 있으면 위험 / 위험은 없지만 공격적 표현이 있으면 주의 / 공격적 표현이 없으면 안전**

**판단 순서**

1. 협박·스토킹·성희롱·자해 유도·개인정보 노출이 있는가? → **위험**
2. 인격·외모·가족·사생활·정체성을 공격하는가? → **위험**
3. 욕설·비꼼·조롱이 포함되어 있는가? → **주의**
4. 공격적 표현 없이 콘텐츠에 대한 의견을 제시하는가? → **안전**

**경계 사례**

| 댓글 | 분류 | 판단 이유 |
| --- | --- | --- |
| 재미없다 | 안전 | 일반적인 콘텐츠 감상 |
| 개노잼 | 주의 | 비속어가 포함된 부정 반응 |
| 설명이 이해하기 어렵다 | 안전 | 구체적인 콘텐츠 피드백 |
| 설명을 왜 이렇게 못하냐 | 주의 | 공격적인 콘텐츠 비판 |
| 넌 머리가 나빠서 설명도 못한다 | 위험 | 개인의 능력과 인격 공격 |
| 오늘 얼굴이 피곤해 보여요 | 안전 | 공격 의도가 없는 관찰 |
| 그 얼굴로 방송을 왜 하냐 | 위험 | 외모를 이용한 개인 공격 |
| 영상 좀 짧게 만들어주세요 | 안전 | 구체적인 요청 |
| 이딴 걸 20분이나 만들었냐 | 주의 | 조롱이 포함된 콘텐츠 비판 |

## 6. AI가 반환해야 하는 결과

안전 / 주의 / 위험 등급과 피드백 여부를 별도로 판단한다.

**필수 반환 항목** — 위험도 / 피드백 존재 / 순화된 피드백 / 분류 사유 / 권장 처리 방식

**분류 사유 코드** — 욕설 · 비속어 · 조롱 · 비꼼 · 개인 공격 · 외모 공격 · 가족 공격 · 성희롱 · 혐오 표현 · 협박 · 스토킹 · 개인정보 노출 · 자해·죽음 유도

## 7. 최종 분류 원칙

# 댓글 분류 파이프라인 v0.1

> **목표:** 안전 댓글은 빠르고 저렴하게 처리하고, 주의·위험 댓글은 한 번 더 검증하여 악성 댓글이 사용자에게 직접 노출되는 것을 최소화한다.

> **기본 원칙:** 사용자 맞춤 기준은 반영하되, 협박·스토킹·성희롱·개인정보 노출 등 명확한 위험 요소는 사용자의 설정으로 완화하지 않는다.

## 전체 구조

```
0. 사용자별 분류 프로필 준비
    ↓
1. 모든 댓글 1차 분류 (Luna + Moderation 병렬)
    ├─ 확실한 안전 → 처리 종료
    └─ 주의·위험·애매한 안전
                   ↓
2. 2차 검증 (Terra)
    ├─ 안전 → 원문 표시
    ├─ 주의 + 피드백 있음 → 순화
    ├─ 주의 + 피드백 없음 → 통계 처리
    └─ 위험 → 숨김·보관·신고 검토
```

## 0. 사용자별 분류 프로필

사용자의 성향을 매번 자유로운 문장으로 전달하지 않고 **구조화된 분류 프로필**로 저장한다.

**저장 항목** — 민감하게 느끼는 공격 대상 / 허용 가능한 욕설·비속어 수준 / 채널에서 자주 사용하는 은어 / 팬들 사이에서 허용되는 장난과 밈 / 반드시 위험으로 처리할 주제 / 원문 노출 허용 수준 / 순화된 댓글의 선호 말투 / 사용자가 직접 분류한 대표 댓글 예시

```json
{
  "protection_level": "high",
  "allowed_slang": ["개웃기다", "미쳤다"],
  "sensitive_topics": ["외모", "가족", "학력"],
  "hide_personal_attacks": true,
  "rewrite_tone": "friendly",
  "emoji_frequency": "medium"
}
```

**적용 원칙**

- 사용자 프로필은 안전과 주의의 경계 조정에 사용한다.
- 협박, 개인정보 노출, 스토킹, 성희롱 등은 사용자 설정과 관계없이 위험으로 처리한다.
- 사용자별 과거 분류 사례 중 현재 댓글과 유사한 예시만 RAG로 가져온다.
- RAG 검색 결과만으로 최종 등급을 결정하지 않는다.
- 사용자 프로필과 분류 기준에는 버전을 부여한다.

## 1. 1차 분류

모든 댓글은 Luna 1차 분류와 `omni-moderation-latest` 검사를 **병렬로** 실행한다.

**Luna 입력** — 댓글 원문 / 영상 정보 / 전체 공통 분류 기준 / 사용자별 분류 프로필 / RAG로 검색한 유사 분류 예시

**Luna 출력**

```json
{
  "candidateLevel": "caution",
  "confidence": 0.72,
  "feedbackPresent": true,
  "locationOrScheduleMention": false,
  "sensitiveTopicMatched": false,
  "hardRiskFlags": [],
  "softRiskFlags": ["profanity"],
  "matchedRules": []
}
```

2차 검증 여부는 모델이 정하지 않는다. **코드가 결정한다.**

## 2. 2차 검증 (Terra)

**검증 방식** — 1차 결과를 그대로 승인하지 않고 별도의 검증 프롬프트로 다시 판단한다. 1차와 다음 중 하나 이상을 다르게 한다: 분류 프롬프트 / 제공하는 예시 / 판단 역할 / 사용하는 모델 / temperature.

**목적** — 주의와 위험의 경계 재판단 / 위험이 안전·주의로 내려가는 오류 감소 / 채널 밈을 악성으로 오해했는지 확인 / 피드백 존재 재확인 / 순화 가능 여부 판단

**최종 등급 확정 규칙**

```
두 판단 일치        → 해당 등급 확정
두 판단 불일치      → 더 높은 보호 등급 적용
협박·스토킹·개인정보·성희롱 확인 → 위험 확정
판단이 계속 애매    → 원문 노출하지 않고 검토 대기
```

## 3. 최종 등급별 처리

| 등급 | 처리 |
| --- | --- |
| 🟢 안전 | 원문 그대로 표시 / 피드백·질문·긍정 반응으로 추가 분류 / 순화 없음 |
| 🟡 주의 + 피드백 있음 | 원문 숨김 / 핵심 피드백 추출 / 별도 순화 모델 호출 / 원문에 없는 칭찬·해결책 금지 |
| 🟡 주의 + 피드백 없음 | 순화 생성 안 함 / 원문 숨김 / 개별 전달 안 함 / 부정 반응 통계에만 포함 |
| 🔴 위험 | 원문 노출 안 함 / 순화 생성 안 함 / 삭제·차단·신고 검토 / 증거 보관 / 협박·스토킹·개인정보는 즉시 알림 |

> 위험 댓글에 피드백이 포함되어 있어도 MVP에서는 개별 순화 댓글로 전달하지 않는다. 여러 위험 댓글에서 동일한 피드백이 반복되는 경우에만 익명화된 종합 의견으로 검토한다.

## 4. 주의 댓글 순화

**최종 등급이 주의이고 실행 가능한 피드백이 있는 댓글에만** 실행한다.

**입력** — 댓글 원문 / 추출된 핵심 피드백 / 사용자 선호 말투 / 이모티콘 사용 빈도 / 최근 생성된 순화 댓글의 문체

**원칙**

- 욕설, 비꼼, 조롱을 제거한다.
- 원문의 핵심 피드백은 유지한다.
- 시청자가 직접 작성한 것처럼 자연스럽게 쓴다.
- 원문에 없는 칭찬이나 호감은 추가하지 않는다.
- `~라는 의견이 있습니다` 같은 보고형 표현은 사용하지 않는다.
- 최근 생성된 문장과 종결 표현이 반복되지 않게 한다.

## 5. 비용 구조

| 등급 | 호출 횟수 |
| --- | --- |
| 확실한 안전 | 1차 분류 1회 |
| 주의 | 1차 1회 + 2차 1회 (+ 피드백 있으면 순화 1회) |
| 위험 | 1차 1회 + 2차 1회 |

> **안전 댓글 대부분은 1회, 위험 댓글은 2회, 순화가 필요한 주의 댓글만 최대 3회 처리한다.**

## 6. RAG 적용 시 주의점

**저장할 것** — 사용자가 직접 수정한 분류 결과 / 사용자가 안전으로 허용한 댓글 / 사용자가 주의·위험으로 변경한 댓글 / 채널 은어와 밈 / 특정 공격 대상에 대한 민감도 / 순화 문체 선호 예시

**의존하지 않을 것** — 협박 / 개인정보 노출 / 스토킹 / 성희롱 / 자해·죽음 유도 / 명확한 혐오 표현 판단. 이 항목들은 사용자별 RAG보다 전체 공통 위험 기준을 우선한다.

> **고정된 공통 기준 + 구조화된 사용자 프로필 + 유사 사례 RAG**

RAG만으로 사용자를 파악하거나, 과거 댓글 전체를 매번 프롬프트에 넣는 방식은 사용하지 않는다.

```
    ↓
안전 댓글의 과잉 차단 감소
    ↓

```

# 댓글 분류 보완 기준 v0.2

## 1. 판단 확신도와 임계값

### 기준

Luna가 반환하는 `confidence`는 최종 정답이 아니라 2차 검증 여부를 결정하는 신호로 사용한다.

- `0.85 이상` — 안전 후보이면서 모든 위험 플래그가 없을 때만 즉시 안전 처리
- `0.85 미만` — Terra 2차 검증
- Luna가 주의 또는 위험으로 판단한 경우 — confidence와 관계없이 Terra 호출
- Moderation이 감지된 경우 — Luna confidence와 관계없이 Terra 호출

> ⚠️ **이 임계값은 아직 실측으로 뒷받침되지 않았다.** 1차 측정 90건에서 0건,
> 반어법 규칙을 넣은 2차에서 1건 발동했다. 10번 실측 기록 참조.
> v0.1에 있던 Luna 0.60 구간은 라우팅을 바꾸지 않아 삭제했다. 검토 대기는 Terra
> 확신도만으로 결정된다.

### Terra 확신도와 검토 대기

Terra 출력에 `confidence`를 추가한다. 이 값이 없으면 "판단이 계속 애매한 경우"를 코드가 알아낼 방법이 없다.

- Terra `confidence`가 `0.60 미만`이면 **검토 대기** 상태로 보낸다.

검토 대기는 **등급이 아니라 상태**다. 안전·주의·위험 중 하나로 확정하지 못한 것이므로 등급 칸을 비워 두고 다음과 같이 처리한다.

- 원문을 노출하지 않는다
- 순화 댓글을 만들지 않는다
- 일반 목록이 아닌 별도 검토 큐에 넣는다
- Luna·Terra 두 판단과 Moderation 결과를 함께 보관해, 사람이 왜 여기 들어왔는지 볼 수 있게 한다

### 안전 즉시 통과 조건

다음을 모두 만족해야 한다.

- Luna 결과가 `safe`
- Luna confidence가 `0.85 이상`
- Moderation `flagged=false` 이고 오류가 아님
- 개인 공격, 욕설, 협박, 개인정보 플래그가 없음
- 위치나 일정에 대한 언급이 없음 *(작성자 이력 기능 보류에 따른 대체 규칙 — 7번 참조)*
- 사용자 민감 주제와 충돌하지 않음

### 예시

| 댓글 | Luna | 그 외 | 결과 |
| --- | --- | --- | --- |
| 마이크 소리가 조금 작게 들립니다. | 안전 0.94 | Moderation 문제 없음 | 안전 즉시 통과 |
| 오늘 얼굴이 좀 안 좋아 보이네요. | 안전 0.72 | 민감 주제 외모 | Terra 검증 |
| 어디 사는지 알고 있다. | 안전 0.88 | 위치·스토킹 감지 | 통과 금지, Terra + 원문 숨김 |
| 이게 무슨 뜻인지 잘 모르겠어요. | 안전 0.55 → Terra 0.48 | — | 검토 대기 |

### 검증 목표

정확도 수치는 아직 정하지 않는다. 팀이 검토·합의한 정답 데이터가 없는 상태에서 목표를 적으면 근거 없는 기준이 굳는다. 정답 데이터를 만드는 절차를 정한 뒤 별도로 다룬다.

지금 확인할 수 있는 것은 둘이다.

- **명확한 협박·개인정보·스토킹이 안전으로 나온 건: 0건**
  이 유형은 판단이 갈리지 않으므로 합의된 정답 데이터 없이도 확인할 수 있다. 가장 먼저 지켜야 할 선이다.
- **검토 대기 비율: 전체의 5% 이하**
  출력 분포만 세면 되므로 정답이 필요 없다. 이보다 높으면 사람이 감당하지 못한다.

### 임계값의 성격

위 수치는 잠정값이다. 조정 방향만 고정한다.

**위험을 안전으로 흘려보내는 쪽보다, 안전을 한 번 더 확인하는 쪽으로 기운다.** 애매하면 임계값을 올려 Terra를 더 부른다.

## 2. Moderation 연동 및 충돌 처리

### 기본 원칙

Moderation은 CrowdSift의 안전·주의·위험 등급을 대신 결정하지 않는다.

Moderation은 유해 콘텐츠 가능성을 찾는 보조 탐지기이고, Luna와 Terra는 댓글의 대상, 의도, 맥락과 사용자 노출 방식을 판단한다.

OpenAI Moderation은 `flagged`, 카테고리별 Boolean, `category_scores`를 반환한다. OpenAI도 점수를 자동 차단 결정이 아닌 애플리케이션 정책의 신호로 사용하도록 안내한다.

### 호출 기준

모든 댓글에 Luna 1차 분류와 `omni-moderation-latest` 검사를 병렬로 실행한다. 다음 중 하나라도 해당하면 Terra를 호출한다.

- Luna가 주의 또는 위험으로 판단
- Luna confidence가 0.85 미만
- Moderation `flagged=true`
- Moderation 호출 실패
- 협박, 위치, 개인정보 패턴 감지
- 사용자 민감 주제와 충돌

### 충돌 분기표

| Luna 결과 | Moderation | 처리 |
| --- | --- | --- |
| 안전·고신뢰 | 문제 없음 | 안전 통과 |
| 안전 | `flagged=true` | Terra 검증, 검증 전 원문 숨김 |
| 주의 또는 위험 | 문제 없음 | Terra 검증 |
| 주의 또는 위험 | `flagged=true` | Terra 검증, 높은 보호 등급 우선 |
| 모든 결과 | Moderation 오류 | 안전 자동 통과 금지, Terra 검증 |

> Moderation 결과가 **없는 것**과 **문제 없음**은 다르게 다뤄야 한다. 오류를 "점수 0"으로 채우면 "검사했더니 안전했다"는 뜻이 되어 위험 댓글이 그대로 통과한다. 오류는 값을 비워 두고 기록한다.

### Moderation 카테고리 처리

| 카테고리 | 처리 |
| --- | --- |
| `harassment` | 최소 주의 후보. 대상과 강도를 Terra가 재판단 |
| `harassment/threatening` | 위험 후보. 원문 즉시 숨김 |
| `hate` | Terra 검증. 정체성 공격이면 위험 |
| `hate/threatening` | 위험 후보. 원문 즉시 숨김 |
| `self-harm/instructions` | 위험 후보 |
| `self-harm/intent` | 작성자 본인의 위기 표현일 수 있음. 6번 참조 |
| `self-harm` | Terra 검증. 대상이 크리에이터면 위험, 작성자 본인이면 6번 참조 |
| `sexual` | 단순 성적 주제와 크리에이터 대상 성희롱을 Terra가 구분 |
| `sexual/minors` | 즉시 숨김 및 별도 검토 |
| `violence` | 영화·게임·뉴스 설명일 수 있으므로 자동 위험 확정 금지 |
| `violence/graphic` | 원문 숨김 후 Terra 검증 |
| `illicit` | Terra 검증. 크리에이터를 향하지 않으면 대개 안전 |
| `illicit/violent` | 위험 후보. 대상 확인은 Terra가 수행 |

### 정책에 없는 카테고리

Moderation의 카테고리는 모델 업데이트로 늘어날 수 있다. 위 목록에 없는 카테고리가 `flagged` 되면 **Terra 검증으로 보낸다.** 모르는 신호를 무시해 통과시키는 것보다 한 번 더 보는 쪽이 싸다.

Moderation에는 개인정보 노출이나 반복 스토킹을 직접 나타내는 전용 카테고리가 없으므로 별도 규칙과 댓글 이력이 필요하다.

## 3. 애매한 표현의 구체적인 기준

### 적용 범위

**언어와 무관하게 같은 기준을 적용한다.** 한국어가 아니어도, 초성·이모지·기호로 우회해도 판단 기준은 동일하다.

### 등급별 조건

**안전** — 공격적 표현이 없음 / 사람의 존재나 고유 특성이 아닌 콘텐츠 또는 수정 가능한 행동을 대상으로 함 / 원문을 그대로 보여줘도 되는 표현임

**주의** — 욕설, 비속어, 비꼼, 조롱이 있음 / 공격 대상이 콘텐츠나 수정 가능한 행동임 / 협박, 성희롱, 외모·가족·정체성 공격은 없음

**위험** — 사람의 존재나 인간적 가치를 공격 / 외모, 신체, 가족, 사생활, 정체성을 공격 / 협박, 성희롱, 스토킹, 개인정보 노출 / 죽음이나 자해를 유도

### 경계 구분 예시

| 댓글 | 분류 | 기준 |
| --- | --- | --- |
| `말이 조금 느려요.` | 안전 | 말하는 속도에 대한 의견 |
| `말 진짜 답답하게 하네.` | 주의 | 행동에 대한 공격적 비판 |
| `너는 정말 답답한 인간이다.` | 위험 | 사람 자체에 대한 공격 |
| `오늘 피곤해 보여요.` | 안전 | 공격 없는 관찰 |
| `그 얼굴로 방송을 왜 하냐.` | 위험 | 외모를 모욕에 사용 |

## 4. 경계 사례 추가 기준

### 인용과 직접 발화의 구분

댓글 안에 위험한 표현이 있어도, **그것을 누가 누구에게 말하는지**를 먼저 본다.

- 다른 사람의 말을 인용하거나 언급하는 것 → 그 자체로 위험이 아니다
- 크리에이터를 향한 직접 발화 → 위험

이 구분이 없으면 악플을 신고하려는 댓글, 표현의 뜻을 묻는 댓글이 전부 위험으로 걸린다.

| 유형 | 댓글 예시 | 분류 및 처리 |
| --- | --- | --- |
| 가린 욕설 | `ㅅㅂ 편집 왜 이래` | 주의, 편집 관련 피드백 추출 |
| 긍정적 비속어 | `오늘 영상 개웃기다` | 공통 기준은 주의, 허용 은어 등록 시 안전 |
| 비꼼 (뒤집는 말이 있음) | `와 설명 진짜 잘한다. 하나도 못 알아듣겠네` | 주의 |
| 비꼼 (뒤집는 말이 없음) | `와 게임 참 잘하시네요` | **안전 통과 금지, Terra 검증.** 등급은 글자 그대로 안전으로 두고 `sarcasm` 표시만 남긴다 |
| 농담형 협박 | `다음에 직접 찾아간다ㅋㅋ` | 위험, 웃음 표현이 있어도 완화하지 않음 |
| 욕설 인용 | `댓글에 "죽어라"라고 쓰는 사람들은 왜 그러죠?` | Terra 검증, 공격 대상과 인용 맥락 확인 |
| 혐오 표현 인용 | `영상에서 나온 혐오 표현의 의미가 궁금해요` | 공격 목적이 아니면 안전 또는 주의 |
| 성적 농담 | `몸매 보려고 영상 본다` | 위험, 신체를 성적으로 대상화 |
| 다국어 협박 | `I know where you live` | 위험 |
| 기호형 협박 | `다음에 보자 🔪` | 위험 |
| 위치 언급 | `오늘도 집 근처에서 봤어요` | **안전 통과 금지, Terra 검증.** 작성자 이력 기능이 보류 상태이므로 단건으로도 보수적으로 다룬다 |
| 팬덤 장난 | `또 게임 못하네ㅋㅋ` | 공통 기준 주의, 확인된 채널 밈이면 안전 |
| 위험+피드백 | `넌 멍청하고 설명도 너무 길다` | 위험 유지, 피드백은 집계 전용 저장소에만 기록 (5번 참조) |
| 자기 위해 표현 | `요즘 사는 게 너무 힘드네요` | 등급 판정과 별개로 `safety_case` (6번 참조) |
| 제3자 대상 공격 | `저 댓글 쓴 사람 진짜 별로다` | 크리에이터 대상이 아니므로 위험 아님. 주의 또는 안전 |
| 자기 비하 | `제가 멍청해서 이해를 못 했네요` | 안전. 공격 대상이 작성자 자신이다 |

### 반어법을 두 갈래로 나누는 이유

`와 설명 진짜 잘한다. 하나도 못 알아듣겠네` 는 칭찬이 같은 댓글 안에서 뒤집힌다.
근거가 본문에 있으므로 1차에서 주의로 정할 수 있다.

`와 게임 참 잘하시네요` 는 다르다. 진심 어린 칭찬과 글자가 같다. 1차에서 주의로
올리면 진짜 팬의 칭찬이 숨겨지고, 안전으로 통과시키면 비꼼이 그대로 노출된다.
어느 쪽으로 정해도 한쪽이 반드시 틀린다.

그래서 **정하지 않는 것을 규칙으로 삼는다.** 등급은 글자 그대로 안전으로 두되
`sarcasm` 표시를 남긴다. 안전 후보에 위험 신호가 붙으면 즉시 통과 조건이 깨지므로
(v0.2 1번 「안전 즉시 통과 조건」 참조) Terra 가 영상 제목과 채널 맥락까지 보고 정한다.
`locationOrScheduleMention` 이 스토킹 의심 댓글을 붙잡는 방식과 같다.

## 5. 피드백 있음·없음 기준

**피드백 있음** — 수정 가능한 문제를 지적함 / 구체적인 요청이 있음 / 콘텐츠에 대한 비교나 선호를 전달함 / 질문을 통해 정보 보완을 요청함 / 공격적 표현을 제거해도 의미 있는 콘텐츠 의견이 남음

**피드백 없음** — 욕설이나 모욕만 존재 / 단순 감정 반응만 존재 / 개선 대상이나 의미를 추출하려면 AI가 내용을 추측해야 함 / 사람에 대한 공격만 존재

### 출력 구조와 담당 단계

네 필드를 한 단계에서 다 뽑지 않는다. 분기에 필요한 것과 최종 결과에 필요한 것이 다르다.

| 필드 | 담당 | 이유 |
| --- | --- | --- |
| `feedback_present` | **Luna (1차)** | 분기 판단에 필요하고, 있음/없음만이라 저렴하다 |
| `feedback_type` | **Terra (2차)** | `actionable` / `preference` / `question` / `none` |
| `feedback_actionable` | **Terra (2차)** | 구체적으로 수정 가능한지 |
| `feedback_core` | **Terra (2차)** | 핵심 피드백 추출은 파이프라인상 Terra의 일 |

Luna에게 핵심 피드백까지 뽑게 하면 어차피 Terra가 재판단하므로 같은 일을 두 번 하는 것이 된다. Luna는 `reasoning: none`으로 도는 저비용 모델이기도 하다.

### 예시

| 댓글 | 존재 | 실행 가능 | 핵심 피드백 |
| --- | --- | --- | --- |
| `편집 개느리네` | 있음 | 있음 | 편집 속도가 느림 |
| `마이크 소리가 작아요` | 있음 | 있음 | 음량이 작음 |
| `이전 영상이 더 재미있었어요` | 있음 | 낮음 | 이전 형식을 더 선호함 |
| `이 내용의 출처가 궁금해요` | 있음 | 있음 | 출처 정보 요청 |
| `개노잼` | 없음 | 없음 | 없음 |
| `너 같은 인간은 싫다` | 없음 | 없음 | 없음 |
| `넌 멍청하고 설명도 너무 길다` | 있음 | 있음 | 설명이 너무 김 |

### 위험 댓글의 피드백 처리

위험 댓글에 피드백이 있더라도 위험 등급은 낮추지 않는다. MVP에서 이 피드백은 **집계 전용 저장소**에만 기록한다.

- 순화 댓글로 만들지 않는다
- 개별 댓글로 크리에이터에게 전달하지 않는다
- 원문과 연결된 채로 저장하되, 화면에는 집계된 형태로만 나타난다 (예: "설명 길이에 대한 지적 4건")
- 순화 피드백 저장소와 **분리된 테이블**을 쓴다. 섞이면 위험 댓글의 내용이 일반 목록에 새어 나갈 수 있다

## 6. 자기 위해 표현(safety_case) 처리

### 왜 분리하는가

`요즘 사는 게 너무 힘들다`처럼 **작성자 본인의 위기를 드러내는 표현**은 크리에이터를 공격하는 것이 아니다. 이것을 악성 댓글로 분류하면 두 가지가 동시에 잘못된다.

- 도움이 필요한 사람이 "차단 검토" 대상이 된다
- 크리에이터에게 자신과 무관한 위기 대응 부담이 넘어간다

### 판정

- Moderation `self-harm`, `self-harm/intent` 감지 → Terra가 대상을 확인
- Terra 판단에서 **위해의 대상이 작성자 본인**이면 `safety_case = true`
- 크리에이터에게 자해를 유도하는 경우는 **위험**이며 safety_case가 아니다

### 처리

`safety_case`는 **등급이 아니라 별도 플래그**다. 안전·주의·위험과 나란히 두지 않는다.

- 크리에이터의 일반 댓글 목록에 **개별로 노출하지 않는다**
- 순화 댓글을 만들지 않는다
- 별도 큐에 저장한다
- 원문을 보존한다

### MVP 범위

저장과 분리까지만 한다. 자동 알림, 상담 자원 안내 발송, 작성자에게 보내는 응답은 범위 밖이다. 잘못 작동하면 피해가 크므로 별도 설계가 필요하다.

## 7. 작성자 이력과 문맥 정보 활용 기준 — 보류

### 보류하는 이유

반복 괴롭힘 판정은 작성자의 과거 이력을 필요로 하는데, **첫 임포트에서는 그 이력이 존재하지 않는다.**

```
첫 임포트: 댓글 90개가 한 번에 들어옴
         → 1번째 댓글을 분류할 때 이력 0건
         → 90번째 댓글을 분류할 때도 이력 0건 (같은 배치라 아직 저장 전)
         → 반복 괴롭힘 판정 0건
```

같은 사람이 다섯 영상에 스토킹 댓글을 달았어도 첫 분석에서는 전부 개별 댓글로 처리된다.

제대로 하려면 **재분석 단계**가 필요하다.

```
1차: 전부 분류하고 저장
2차: 작성자별로 다시 훑어 반복 패턴이 있으면 재판정
```

파이프라인에 없는 새 단계이므로 별도로 설계한 뒤에 진행한다.

### 조건에서 제외한 항목

- ~~차단 이후 **다른 계정**에서 다시 접근~~ → YouTube는 새 계정이 같은 사람인지 알려주지 않는다. 추적 수단이 없다. (다른 **영상**에서의 재접근은 추적 가능하므로 유지)

### 지금부터 쌓아 둘 것

기능은 보류하되 나중에 소급 집계할 수 있도록 **데이터는 지금부터 저장한다.** 아래는 이미 저장되고 있다.

- 작성자 채널 ID / 댓글 작성 시각 / 댓글이 작성된 영상 ID

재분석 설계 시 추가로 필요한 것: 과거 주의·위험 판정 횟수 / 위치·가족·외모 관련 언급 이력 / 차단·신고 이력

### 현 단계의 대체 규칙

- **위치나 일정 언급이 있으면 안전 즉시 통과를 금지하고 Terra로 보낸다**
- 협박 또는 개인정보 노출은 반복 여부와 관계없이 즉시 위험

> 사용자 개인화는 안전과 주의의 경계만 조정한다. 협박, 스토킹, 개인정보 노출, 성희롱 등 명확한 위험 요소는 개인화로 낮추지 않는다.

## 8. 동작 검증

- Luna confidence 임계값 테스트
- Terra confidence 임계값 및 검토 대기 동작 테스트
- Moderation과 Luna/Terra 충돌 테스트
- Moderation 오류 시 안전 자동 통과가 차단되는지 테스트
- 정책에 없는 카테고리가 Terra로 넘어가는지 테스트
- 위치·일정 언급이 안전 즉시 통과를 막는지 테스트
- `safety_case`가 일반 목록에 노출되지 않는지 테스트
- 명확한 협박·스토킹·개인정보 사례의 안전 오분류 0건
- Moderation 모델 변경 시 category score 임계값 재검증
- 사용자에게 노출되는 모든 위험 원문은 기본 숨김 처리

## 9. 운영 위험과 보류 항목

### 운영 위험

**Moderation 장애 시 비용 급증** — Moderation이 실패하면 안전 자동 통과가 막히므로 모든 댓글이 Terra로 간다. 무료 필터가 죽어서 가장 비싼 모델을 전건 호출하는 상황이 된다. 안전 판단으로는 옳지만 비용 위험이 있으므로 연속 실패를 감지하면 임포트를 중단하고 알린다. Moderation 실패율을 기록한다.

**신규 채널의 콜드 스타트** — 허용 은어와 유사 사례가 비어 있는 새 채널에서는 `개웃기다` 같은 칭찬형 비속어가 주의로 분류되어 숨겨진다. 주의 + 피드백 없음이면 통계로만 잡히므로 칭찬이 크리에이터에게 전혀 도달하지 않는다. 첫 사용 경험에 직접 영향을 주므로 실측 후 조정이 필요하다.

**Moderation 모델 업데이트** — OpenAI는 기반 모델이 계속 업데이트될 수 있다고 안내한다. `category_scores` 기반 자체 임계값은 주기적으로 재조정한다.

### 보류 항목

| 항목 | 사유 | 선행 조건 |
| --- | --- | --- |
| 작성자 이력 기반 반복 괴롭힘 | 첫 임포트에 이력이 없음 | 재분석 단계 설계 |
| 답글 맥락 반영 | 기준 문서에 규정 없음 | 답글 규정 확정 |
| 정확도 측정 기준 전반 | 정답 데이터 없음 | 정답 데이터 구축 절차 확정 |
| safety_case 자동 알림 | 오작동 피해가 큼 | 별도 설계 |

# 10. 실측 기록

표본: `docs/test-comment-plan.md`의 테스트 댓글 90건 (정답 데이터가 아니라 참고용 라벨)

## 2026-08-05 · Luna 1차 + Moderation

모델: `gpt-5.6-luna` (reasoning: none), `omni-moderation-latest`

### 확신도가 라우팅 신호로 작동하지 않는다

```
0.95 ~ 0.99   89건
0.90 ~ 0.94    1건
```

- 최저 0.90 / 중앙 0.99, 서로 다른 값은 **5개뿐**
- `luna_low_confidence`로 Terra에 간 건 **0건** — 0.85 문턱이 한 번도 발동하지 않았다
- 같은 댓글이 실행마다 0.82와 0.90 이상으로 갈렸다. **모델이 만드는 흔들림이 우리가 그은 선보다 크다**

정확도와는 별개 문제다. Luna는 등급을 대체로 맞게 골랐지만, **틀렸을 때도 0.98~0.99를 적었다.**

| 판정 | 댓글 | 확신도 |
| --- | --- | --- |
| 맞음 | 넌 머리가 나빠서 설명도 못한다 → 위험 | 0.99 |
| 맞음 | 그냥 죽어라 → 위험 | 1.00 |
| **틀림** | 와 편집 참 잘하셨네요 → 안전 (반어법) | 0.99 |
| **틀림** | 와 게임 참 잘하시네요 → 안전 (반어법) | 0.98 |

확신도가 정확도를 따라가지 않으므로 "자신 없으니 한 번 더 봐달라"는 신호로 쓸 수 없다.

### 분기 결과

```
즉시 안전 확정 : 40건 (44.4%)
Terra 로 넘김  : 50건 (55.6%)

넘긴 이유:
  luna_caution                 28건
  luna_danger                  20건
  moderation_flagged            5건
  location_or_schedule_mention  3건
  risk_flag_on_safe_candidate   1건
```

Terra행의 96%가 후보 등급 때문이고 확신도 기여는 0이다.

### Moderation은 한국어 위험을 거의 못 본다

90건 중 5건(5.6%)만 걸었고, 위험으로 적어둔 26건 중에는 3건이었다.

**놓친 것 — 점수가 문턱 아래가 아니라 사실상 0이다**

| 댓글 | 최고 점수 |
| --- | --- |
| 어디 사는지 알고 있다 | illicit 0.002 |
| 카페 위치 보니까 어디 사는지 대충 알겠네 | illicit 0.004 |
| 다음에 직접 찾아간다 | violence 0.010 |
| 옷차림이 좀 그렇네요. 노리고 입은 거죠? | harassment 0.059 |

모더레이션에는 스토킹·개인정보 범주가 없고, 위협인지는 어휘가 아니라 맥락이 정한다.

**관용구를 글자 그대로 읽는다**

| 댓글 | 판정 | 실제 |
| --- | --- | --- |
| ㄹㅇ 편집 답답해 죽는 줄 | self-harm 걸림 | 관용구 |
| 발컨 실화냐 진짜 | violence 걸림 | 게임 은어 |
| 편집 개느리네 | sexual 0.182 | `개-` 접두어 |

**등급별 최고 점수 — 위험이 주의보다 낮다**

```
안전  25건 · 걸림 0건 · 중앙 0.010
주의  27건 · 걸림 2건 · 중앙 0.056
위험  26건 · 걸림 3건 · 중앙 0.016
```

주의 댓글이 더 높게 나오는 이유는 위험해서가 아니라 어휘가 걸려서다. 따라서 **한국어에서는 `category_scores` 임계값을 조정해도 위험과 주의가 갈라지지 않는다.**

다만 이 구조에서 모더레이션 오류는 **모두 안전한 방향으로 떨어진다.** 오탐은 Terra 한 번을 더 부를 뿐이고, 미탐은 Luna가 이미 잡는다. 무료이므로 유지한다.

### 위치 언급 표시가 스토킹을 건졌다

| 댓글 | Luna 후보 | 모더레이션 | 결과 |
| --- | --- | --- | --- |
| 어디 사는지 알고 있다 | 위험 | 0.002 | Luna가 잡음 |
| 그러게 어디 사는지 궁금하네 | **안전** | 0.001 | 위치 표시로 Terra행 |
| 저번에 그 동네에서 봤는데 | **안전** | 0.008 | 위치 표시로 Terra행 |

무료 필터에 기댔으면 셋 다 통과했다. 7번의 대체 규칙이 실측으로 정당화되었다.

### 확인된 프롬프트 구멍

- **반어법** — 경계 사례 표에는 있으나 Luna 프롬프트에 없다. 2건 모두 놓쳤다
- **칭찬형 비속어의 일관성** — `아 개웃겨`는 안전, `존나 웃기다`·`미쳤다 진짜`·`ㅁㅊ`는 주의. 같은 성격의 표현인데 낱말마다 갈린다

Luna 183회 호출에 약 35만 토큰, $0.02. 모더레이션은 무료다.

## 2026-08-05 (2차) · 반어법 규칙을 넣고 다시 잼

바꾼 것은 프롬프트 한 곳뿐이다. `crowdsift-luna-first-pass-v2` → `v3`, 「칭찬처럼
보이는 말」 절 추가. 코드와 문턱값은 그대로 두었다. 무엇이 무엇을 움직였는지 보려고
한 번에 하나만 바꿨다.

### 반어법 2건이 즉시 통과에서 빠졌다

```
A30  와 편집 참 잘하셨네요   safe 0.86  soft ["sarcasm"]
     → risk_flag_on_safe_candidate

C30  와 게임 참 잘하시네요   safe 0.82  soft ["sarcasm"]
     → luna_low_confidence, risk_flag_on_safe_candidate
```

`matchedRules` 에 **"같은 댓글 안에서 뒤집는 말이 없어 글자 그대로 safe 로 판정"** 이라고
직접 적었다. 규칙이 읽혔다는 증거다.

주의로 올리지 않고 표시만 남기는 방식이 의도대로 작동했다. 등급은 여전히 안전이므로
진짜 칭찬이었다면 크리에이터에게 그대로 닿고, 비꼼이었다면 Terra 가 영상 제목까지 보고
정한다. 1차에서 둘 다 0.98~0.99로 즉시 통과했던 것과 대비된다.

### 확신도가 처음으로 정보를 담았다

| | 1차 (v2) | 2차 (v3) |
| --- | --- | --- |
| 서로 다른 값 | 5개 | 7개 |
| 최저 | 0.90 | 0.84 |
| 0.85 미만 | 0건 | 1건 |
| `luna_low_confidence` 발동 | **0건** | 1건 |

낮은 값이 붙은 곳이 하필 판단이 실제로 어려운 자리였다. A30 0.86, C30 0.82,
B08 `저번에 그 동네에서 봤는데` 0.80. 1차에서 이 셋은 전부 0.98 이상이었다.

다만 **1건으로 문턱값을 정당화할 수는 없다.** 0.85 선은 여전히 관찰 대상이며,
확신도를 3단(`clear` / `borderline` / `unclear`)으로 바꾸는 실험은 남아 있다.

### 칭찬형 비속어가 한 줄로 정렬됐다

| 댓글 | 1차 | 2차 |
| --- | --- | --- |
| 아 개웃겨 ㅋㅋㅋㅋ | 안전 | **주의** |
| 존나 웃기다 진짜 | 주의 | 주의 |
| 미쳤다 진짜 ㅋㅋㅋ | 주의 | 주의 |
| ㅁㅊ 이걸 무료로 본다고? | 주의 | 주의 |

기준 문서의 「긍정적 비속어 → 공통 기준 주의, 허용 은어 등록 시 안전」과 맞았다.
낱말마다 갈리던 것이 사라졌다.

이것이 **신규 채널 콜드 스타트 문제를 그대로 드러낸다.** `allowedSlang` 이 비어 있으면
칭찬 4건이 모두 숨겨진다. 규칙이 틀린 게 아니라, 허용 은어를 채우는 경로가 아직 없는
것이다. 8번의 미결 항목과 같은 사안이다.

**나머지 차이를 프롬프트 탓으로 돌리면 안 된다.** 1차에서 같은 댓글이 실행마다
0.82와 0.90 이상으로 갈린 것을 이미 봤다. 후보 등급도 같은 폭으로 흔들린다.
